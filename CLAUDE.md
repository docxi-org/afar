# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проект

**afar** — двухпанельный консольный файловый менеджер в духе Far Manager (Rust, TUI) со встроенным ИИ-агентом: настоящий `claude` CLI работает в нижней панели во встроенном терминале, afar даёт ему MCP-сервер и хуки. Замысел, архитектура, раскладка клавиш и план этапов — в `docs/` (на русском; начинать с `docs/README.md`). Сейчас готов прототип M0, следующий этап — M1 (файловые операции, `docs/06-roadmap.md`).

`FarManager/` — справочная копия исходников Far Manager 3 (BSD-3), в репозиторий не входит. Использование как эталона и требования лицензии — `docs/07-far-reference.md`.

План работ — `TODO.md` (чекбоксы по этапам); выполненное переносится в `READY.md` (новое сверху, с датой и коммитом) — обновлять оба файла вместе с работой.

**Настройки** — `%APPDATA%\afar\config.toml` (`src/config.rs`, шаблоны с комментариями `i18n/config/<язык>.toml`; новый параметр — в структуру, оба шаблона и тест `templates_are_the_defaults`); состояние прошлого запуска — `%LOCALAPPDATA%\afar\state.json`. В проверках задавать и `APPDATA`, и `LOCALAPPDATA` во временные каталоги.

**Локализация** (`src/i18n.rs`, `docs/02-architecture.md`): никаких строк интерфейса в коде — только `tr!("id", аргументы…)`. Свои строки afar — в `i18n/en.ftl` и `i18n/ru.ftl` (Fluent, английский — базовый); строки Far — по идентификаторам Far (`MCopyDlgTitle`, …) из `i18n/far/<язык>.ftl` на 13 языках, генерируются `python tools/far_lng.py gen i18n/far-ids.txt i18n/far` (новый идентификатор — добавить в `i18n/far-ids.txt`; найти по тексту — `python tools/far_lng.py find <текст>`). Язык: `AFAR_LANG`, иначе язык интерфейса Windows, иначе английский. Не переводится только то, что читает модель (MCP, журнал, системный промпт).

Пользователь общается на русском; документация и тексты интерфейса — на русском, комментарии в коде — на английском.

## Команды

Окружение: Windows 11, Git Bash. Если `cargo` не в `PATH` — `export PATH="$HOME/.cargo/bin:$PATH"`.

```
cargo build                      # отладочная сборка
cargo run --release              # запуск (в Windows Terminal)
cargo test                       # все тесты
cargo test keys::tests::encodes_mouse   # один тест
cargo fmt                        # форматирование (rustfmt по умолчанию)
cargo clippy
```

### Режим разработки

Пользователь обычно держит запущенным `cargo run --release -- --dev` (`src/dev.rs`): процесс-супервизор отодвигает свой `exe` (переименованием) и запускает приложение из копии в `%TEMP%\afar-dev`, приложение само собирает `cargo build` того же профиля при изменении исходников и перезапускается с сохранением состояния (`DevState`), агент продолжает разговор по своему `--session-id` через `--resume`. Значит, правки в `src/` сразу пересобирают и перезапускают afar у пользователя; ломающая сборку правка видна ему как ошибка на экране пользователя. Собственные `cargo build` не мешают (общая блокировка каталога `target`).

### Проверка интерфейса без человека

TUI проверяется программой `examples/pty_probe.rs`: она запускает процесс в ConPTY, «нажимает клавиши» и печатает экран эмулятора.

```
MSYS_NO_PATHCONV=1 PROBE_INPUT='dir /b\r||^O' cargo run -q --example pty_probe -- 9 target/debug/afar.exe
```

- `PROBE_INPUT` — шаги через `||`, по одному в секунду начиная с трети времени; `\r` — Enter, `^X` — Ctrl+X, `^@` — Ctrl+Space (фокус на агента), `^[` — ESC (например, мышь: `^[[<0;6;6M^[[<0;6;6m` — щелчок по колонке 6, строке 6).
- `PROBE_CELLS="row,col;…"` — печатает цвета ячеек.
- `MSYS_NO_PATHCONV=1` обязателен: иначе Git Bash превращает `/c` в путь.
- Каждый запуск afar создаёт сессию в `%LOCALAPPDATA%\afar\sessions\<время>\`: `journal.jsonl`, `output\cmd-N.log`, `mcp.json` (порт и токен MCP), `settings.json` (хуки), `keys.log` при `AFAR_DEBUG_KEYS=1`. По `mcp.json` можно проверять MCP-сервер curl'ом. История команд — `%LOCALAPPDATA%\afar\history\commands.txt`: в проверках, которые запускают команды, задавать `LOCALAPPDATA` во временный каталог (Windows-путь), чтобы не засорять историю пользователя.
- Файловые операции проверять только в песочнице, не в каталоге проекта (на `C:` мало места — большие файлы только на `F:`, например `target/`): `mkdir "$TEMP/afar-sandbox"`, `cd` туда и запускать уже собранные `target/debug/examples/pty_probe.exe` и `afar.exe` по Windows-пути (`'F:\AGI\far\target\debug\afar.exe'`, путь вида `/f/...` CreateProcess не понимает).
- `AFAR_PTY_RAW=<файл>` — сырой вывод программ в PTY (и afar в `pty_probe`) дописывается в файл: видно, что именно прислал ConPTY.
- `tools/mcp_call.sh <каталог сессии> <инструмент> '<json>'` — вызов MCP-инструмента запущенного afar без модели (например, `afar_delete` в паре с `PROBE_INPUT='\r'`, подтверждающим диалог). `curl` здесь — Windows-бинарник: временные файлы только в `%TEMP%`, не `/tmp` и не `/dev/null`.
- В проверках запускать afar с `AFAR_NO_AGENT=1` (агент не стартует, пока не нажать Enter в его панели), если тест не про агента: короткие запуски, убитые во время старта `claude`, сбивают его полноэкранный режим у пользователя («fullscreen renderer didn't finish starting»).
- Запуск afar поднимает настоящий `claude`; запросы модели в тестах расходуют лимит пользователя — делать их только при необходимости.

## Архитектура

Один крейт (`src/lib.rs` + `src/main.rs`); разделение на workspace из `docs/02-architecture.md` — позже.

- **Один владелец состояния.** Всё состояние в `App` (`app.rs`) и меняется только в главном цикле. Фоновые потоки (ввод crossterm, читатели PTY, MCP-сервер на tokio) лишь шлют `AppMsg` в `mpsc`-канал; MCP-запросы приходят как `AppMsg::Mcp` с `oneshot`-каналом для ответа. Не трогать состояние из других потоков.
- **`term.rs`** — `PtySession`: процесс в псевдоконсоли (`portable-pty`) + эмулятор `vt100`. Поток-читатель всегда вычитывает вывод и отвечает на запросы терминала (`Replies`: DSR `CSI 6n` — ConPTY ждёт ответа при старте, DA, OSC 10/11). Поток-ожидатель после выхода процесса закрывает псевдоконсоль (иначе ConPTY не отдаёт EOF).
- **Команды командной строки**: каждая — отдельный процесс `cmd /c %AFAR_CMD%` в своей PTY (текст команды — через переменную окружения: `portable-pty` экранирует аргументы по правилам MSVCRT, которые `cmd.exe` не понимает). «Экран пользователя» (`Ctrl+O`) = текст завершённых команд + живой экран текущей. Общий эмулятор на несколько ConPTY-сессий не работает — ConPTY перерисовывает экран и затирает чужой вывод.
- **Захват вывода**: строки, уходящие за верх экрана, забираются через доработку `vt100` (`set_line_capture` / `take_scrolled_lines`) + итоговый экран (`termview::screen_lines`). Это то, что видел пользователь, без полос прогресса и VT.
- **`vendor/vt100`** — копия vt100 0.16.2 (MIT) с доработками, помеченными `AFAR-PATCH`: захват строк и печать U+FFFD (оригинал её выбрасывает, и строка съезжает относительно программы). Не заменять на версию с crates.io.
- **`vendor/crossterm`** — копия crossterm 0.29.0 (MIT, подключена через `[patch.crates-io]`, её же использует ratatui): в Windows клавиши цифрового блока помечаются `KeyEventState::KEYPAD` (`AFAR-PATCH`), иначе серые `+`/`-`/`*` Far не отличить от обычных; нажатия и отпускания самих `Shift`/`Ctrl`/`Alt` приходят как `KeyCode::Modifier` (тоже `AFAR-PATCH`) — по ним строка клавиш показывает подписи Far для зажатых модификаторов (`App::held`), в `on_key` они не попадают. В `pty_probe` такие клавиши посылаются в формате win32-input-mode ConPTY: серый `+` — `^[[107;78;43;1;0;1_^[[107;78;43;0;0;1_` (нажатие и отпускание; `106;55;42` — серый `*`, `109;74;45` — серый `-`).
- **`keys.rs`** — клавиши и мышь → xterm-последовательности для программ в PTY; `normalize` сопоставляет кириллицу (ЙЦУКЕН) латинским клавишам для Ctrl/Alt-сочетаний (с русской раскладкой `Ctrl+O` приходит как `Ctrl+Щ`).
- **Диалоги и операции**: `dialog.rs` — диалог в стиле Far (элементы, клавиши, мышь, отрисовка); `ops/` — файловые операции в фоновом потоке (`mod.rs`: `Worker` с прогрессом и вопросами, `delete.rs`, `copy.rs` с `plan_targets` — проверки до начала), сообщения `OpMsg` (прогресс, вопросы об ошибке и о существующем файле — поток ждёт ответа, итог); `app/fileops.rs` — оверлей `App` (стек `overlays`: диалоги с `Purpose` — что делать при закрытии, окна прогресса), F7/F8, `afar_mkdir`/`afar_delete`/`afar_copy`/`afar_move`. Пока есть оверлей, клавиши и мышь идут ему, кроме фокуса на агенте. Запросы агента, ждущие пользователя (`Request::Delete`, `Request::Copy`), отвечают позже — oneshot-отправитель хранится в `Purpose`/`RunningOp`.
- **Слежение и правки агента** (`watch.rs`, `app/fswatch.rs`): `notify` следит за каталогами панелей (не рекурсивно), изменения перечитывают панели и идут в журнал с автором (агент / пользователь / внешнее; операции afar не дублируются); хуки `PreToolUse` (Bash) и `PostToolUse` (правки и Bash агента) → `AgentToolUsed`, изменённые агентом файлы подсвечиваются. Хуки вызываются без модели: POST `/hook/post-tool` с JSON входа хука и токеном из `mcp.json`.
- **Команды и раскладка** (`command.rs`, `keymap.rs`, `app/commands.rs`): у каждого действия панелей — постоянное имя и клавиши Far в таблице `COMMANDS`; `panels_key` ищет команду по сочетанию (`Chord`) и выполняет `run_command`, иначе клавиша уходит командной строке (`app/cmdline.rs`). Новую клавишу панелей — только через `COMMANDS`, не через `match` по клавишам.
- **Разрешения агента** (`app/policy.rs`): обработчики MCP-запросов, меняющих файлы, сначала спрашивают `permission(AgentAction)` — разрешить сразу, диалог или отказ. Новый инструмент агента, который что-то меняет, — только через эту проверку.
- **`journal.rs`** — журнал событий (в памяти + JSONL); `format_entries` — компактный текст для агента.
- **`mcp.rs`** — MCP-сервер (`rmcp`, Streamable HTTP через `axum` на `127.0.0.1`, случайный порт, bearer-токен) с инструментами `afar_*`, эндпоинт `/hook/{event}` и клиент хуков `afar hook <event>` (печатает JSON `hookSpecificOutput.additionalContext`).
- **Агент** запускается как `claude --settings <session>/settings.json --append-system-prompt … --mcp-config <session>/mcp.json` (`--mcp-config` вариадический — держать последним), с `AFAR_ENDPOINT`/`AFAR_TOKEN` в окружении и без служебных переменных внешней сессии Claude Code (`CLAUDE_SESSION_VARS` в `app.rs`). Глобальные настройки `~/.claude` не трогаются; единственное исключение — свой временный lock-файл протокола IDE в `~/.claude/ide/` (`[agent] ide`), удаляемый при выходе. В проверках, которые убивают afar, удалять его после (по точному пути: файлы с `"ideName": "afar"`).
- **Связь с Claude Code сверх MCP и хуков** (`ide.rs`, `app/ide.rs`, `docs/11-viewer-editor.md` «Связь с Claude Code»): протокол IDE — WebSocket MCP-сервер, агент получает `CLAUDE_CODE_SSE_PORT`; Channels — `afar channel` (stdio MCP-сервер в `mcp.json`, забирает события длинным опросом `/hook/channel-wait`), агент запускается с `--dangerously-load-development-channels server:afar-channel` (вопрос `claude` о канале разработки при старте afar по `[agent] confirm_channels` подтверждает сам — `App::confirm_dev_channels`). Обмен по протоколу IDE — в `<сессия>/ide.log`.
- Режимы наблюдения: on-demand (хук сообщает только число новых событий) и live (`afar:live` в командной строке — хук добавляет записи журнала и хвост вывода упавших команд).
- **Просмотрщик** (`viewer/`, `app/viewers.rs`, `docs/11-viewer-editor.md`, справка по Far — `docs/12-far-viewer-reference.md`): как в Far, верх экрана — байтовое смещение, строки находятся сканированием от него (`layout.rs`), файл читается блоками (`source.rs`), кодовые страницы Windows — `codepage.rs` (определение: BOM → UTF-8 → UTF-16 → `chardetng`), поиск — в фоновом потоке (`search.rs`, результат — `AppMsg::ViewerFound`). Каждый просмотрщик — свой экран в `Wm` (`ScreenId::Viewer`); клавиши — команды контекста `Ctx::Viewer`. Позиции файлов — `%LOCALAPPDATA%\afar\history\viewer.json`.
- **Сессия агента** (`app/agent.rs`, `app/agentmenu.rs`, `claude_sessions.rs`, `docs/13-agent-sessions.md`): всё о запущенном `claude` — в `AgentSession` (`self.agent`: процесс, id и имя сессии, каталог, режим разрешений, журнал, IDE, Channels); запуск — `launch_agent(каталог, Launch::Fresh | Resume(id))`. Меню панели агента (`F9` на агенте, щелчок по верхней рамке агента) набирает команды Claude Code (`/rename`, `/model`, …) в его поле ввода. Сессии каталога и их имена — из `~/.claude/projects/<каталог>/*.jsonl`. Несколько сессий — позже, поэтому новое состояние агента — в `AgentSession`, не в `App`.
- **Истории** (`history.rs`, `docs/15-history-autocomplete.md`): одна база SQLite `%LOCALAPPDATA%\afar\history.db` (`App::store`) для полей диалогов и команд. Поле с историей — `input_at(…, Some("ИмяСписка"))` (имена Far: `Copy`, `NewFolder`, `Masks`, …), `.use_last()` — последняя запись в пустое поле; диалог просит историю через `Outcome::History`, `App::dialog_history` отвечает, запись — при закрытии кнопкой (`record_dialog_history`).
- **Автозавершение** (`complete.rs` — подбор вариантов, `completion.rs` — список, `app/autocomplete.rs` — связка): после правки командной строки или поля диалога `App::autocomplete` пересчитывает список (`self.completion`); пока он открыт, клавиши сначала идут ему (`completion_key`). Признаки полей: `.path()` — файлы, `.exec()` — ещё и программы.
- **Оверлеи модальны и для панели агента**: пока открыт диалог или меню, мышь и клавиши (кроме уже идущего вывода) получает только оверлей; фокус на агента не переводится.
- **Оконный менеджер** (`wm.rs`, `docs/08-windows.md`): дерево разбиений с перетаскиваемыми разделителями, экраны (панели / экран пользователя; позже просмотрщики, редакторы) в слоте экрана, закреплённая панель агента. `Wm::arrange` даёт прямоугольники окон, `App::layout` добавляет командную строку и строку клавиш. Новые окна — через `WinId` и дерево, а не жёсткие координаты.
- **Отрисовка** (`panel.rs`, `theme.rs`, `termview.rs`, `tui.rs`): ratatui; кадр — одна запись в обёртке `?2026` (`Tui::draw`), экраны PTY рисуются через `term::view` (снимок во время синхронного кадра программы). Цвета — только из `theme.rs` (палитра Far из `FarManager/far/palette.cpp`, раскраска из `hilight.cpp`); цвета Far заданы в порядке консоли Windows — через модуль `con`, не напрямую `Color::Yellow` (это тёмно-жёлтый ANSI); рамка панели агента синяя, внутри — цвета терминала по умолчанию. Геометрия последнего кадра (`last_layout`) используется для попадания мышью.
