# 07. Far Manager как эталон

## Почему не форк

Исходники Far Manager 3.0 (сборка 6741, коммит от 05.10.2026) изучены в `../FarManager/`. Ключевые архитектурные ограничения для встраивания агента:

| Ограничение | Где в коде Far |
|---|---|
| Внешняя команда запускается в той же консоли, главный поток ждёт её завершения | `far/execute.cpp:611` (`CREATE_NEW_CONSOLE` только для запуска без ожидания), ожидание — `wait_for_process` (~372) |
| «Экран пользователя» — снимок консоли за панелями, а не живой терминал | `far/console_session.cpp:75-203`, `far/desktop.cpp:76-106` |
| Нет псевдоконсоли (ConPTY) и разбора входящего VT | `CreatePseudoConsole` не используется нигде; VT в Far — только вывод (`far/console.cpp`) |
| Раскладка панелей жёстко привязана к `ScrY` и уменьшению высоты панелей | `FilePanels::SetScreenPosition/SetPanelPositions`, `far/filepanels.cpp:223-285` |
| Редактор и просмотрщик всегда занимают весь экран | `far/fileedit.cpp:424, 896, 2081`, `far/fileview.cpp:168, 331` |
| Плагины не получают событий о файловых операциях; событие смены каталога только у LuaMacro и без пути | `Copy()` `far/copy.cpp:3512` без уведомлений; `SE_FOLDERCHANGED` `far/manager.cpp:1244` |
| События панели (`FE_*`) получает только плагин, которому принадлежит панель | `far/filelist.cpp:6835-6841`, `far/plugins.cpp:1230-1238` |
| Нет внешнего канала управления; вызовы API — только из главного потока через `ACTL_SYNCHRO` | `far/plugapi.cpp:409-413`, `far/notification.cpp:137-164` |

Объём ядра — около 199 тыс. строк C++ (без сторонних библиотек), плюс плагины. Встраивание агента в форк требует переделки оконного менеджера, раскладки, запуска процессов и добавления точек событий по всему ядру.

## Как использовать Far при разработке afar

1. **Справка как спецификация поведения.** `far/FarEng.hlf.m4` и `far/FarRus.hlf.m4` описывают поведение клавиш, диалогов и режимов. Для каждой реализуемой функции сначала читаем соответствующий раздел справки.
2. **Исходники как ответ на «как Far обрабатывает этот случай».** Полезные места:

| Тема | Файлы Far |
|---|---|
| Раскладка панелей, клавиши `Ctrl+стрелки` | `far/filepanels.cpp` |
| Файловая панель: сортировка, режимы вида, выделение, быстрый поиск | `far/filelist.cpp`, `far/panel.cpp`, `far/fastfind.cpp` |
| Маски файлов | `far/filemasks.cpp` |
| Копирование и перемещение (конфликты, ошибки, ссылки) | `far/copy.cpp`, `far/copy_progress.cpp` |
| Удаление (только для чтения, корзина, ссылки) | `far/delete.cpp` |
| Атрибуты | `far/setattr.cpp` |
| Командная строка, встроенные команды | `far/cmdline.cpp`, `far/execute.cpp` |
| Ассоциации файлов | `far/filetype.cpp` |
| История | `far/history.cpp` |
| Просмотрщик | `far/viewer.cpp` |
| Редактор | `far/editor.cpp`, `far/fileedit.cpp` |
| Поиск файлов | `far/findfile.cpp` |
| Раскраска файлов | `far/hilight.cpp` |
| Палитра по умолчанию | `far/palette.cpp`, `far/farcolor.hpp` |
| Ширина символов | `far/char_width.cpp` |

3. **Клавиатура и внешний вид** — сверяем с запущенным Far рядом (скриншоты в `docs/assets/` по мере необходимости).

## Лицензия

Far Manager распространяется под **BSD 3-Clause**. При переносе алгоритмов или фрагментов кода из Far в afar:

- сохраняем уведомление об авторских правах Far Group и текст лицензии (файл `THIRD-PARTY-NOTICES.md` в корне afar, ссылка из соответствующего исходного файла);
- не используем название «Far Manager» и имена авторов для продвижения afar без разрешения (третий пункт лицензии);
- переписывание поведения по справке (без копирования кода) уведомления не требует, но источник всё равно указываем в комментарии.

Лицензия afar должна быть совместима с этим (MIT или BSD-3-Clause — см. открытые вопросы в [README.md](README.md)).
