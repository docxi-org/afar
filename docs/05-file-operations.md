# 05. Файловые операции и виртуальная ФС

Файловые операции — то, где файловый менеджер не имеет права ошибаться. Требования здесь строже, чем к остальному коду.

## Виртуальная ФС (`afar-vfs`)

Панель показывает не «путь на диске», а местоположение в некоторой ФС. С первого дня используется трейт, даже если реализация одна — локальная:

```rust
pub struct VfsPath { pub fs: FsId, pub path: PathBuf }

#[async_trait]
pub trait Vfs: Send + Sync {
    fn caps(&self) -> VfsCaps;  // atomic_rename, symlinks, trash, attrs, case_sensitive
    async fn list(&self, dir: &Path) -> Result<BoxStream<'_, Result<Entry>>>;  // потоково: большие каталоги
    async fn stat(&self, p: &Path) -> Result<Entry>;
    async fn open_read(&self, p: &Path) -> Result<Box<dyn AsyncRead + Unpin + Send>>;
    async fn create_write(&self, p: &Path, mode: WriteMode) -> Result<Box<dyn AsyncWrite + Unpin + Send>>;
    async fn mkdir(&self, p: &Path) -> Result<()>;
    async fn remove(&self, p: &Path, kind: RemoveKind) -> Result<()>;   // File | EmptyDir | ToTrash
    async fn rename(&self, from: &Path, to: &Path) -> Result<()>;
    async fn set_attrs(&self, p: &Path, a: &AttrChange) -> Result<()>;
}
```

| Реализация | Этап | Основа |
|---|---|---|
| `LocalFs` | M0 | `std::fs` / `tokio::fs`; на Windows — дополнительно WinAPI через крейт `windows` (атрибуты, `CopyFileExW`, идентификаторы файлов) |
| `ArchiveFs` (zip, 7z, tar…) | M4 | `zip` / `tar` / `7z.dll` (на Windows) или `libarchive` |
| `SftpFs` | M5 | `russh` + `russh-sftp` |

Копирование между разными ФС идёт через `open_read` → `create_write`; внутри `LocalFs` — быстрый путь через системные вызовы.

### Элемент каталога

```rust
pub struct Entry {
    pub name: OsString,
    pub kind: EntryKind,        // File | Dir | Symlink { target, to_dir } | Junction | Other
    pub size: u64,
    pub modified: Option<SystemTime>,
    pub created: Option<SystemTime>,
    pub attrs: Attrs,           // readonly, hidden, system, archive, compressed, encrypted / unix mode
    pub file_id: Option<FileId>,// (том, индекс) — для обнаружения «копирования файла в самого себя» и жёстких ссылок
}
```

## Движок операций (`afar-ops`)

### Жизненный цикл операции

```
 Запрос (Invocation) ──► Проверки ──► План ──► Выполнение ──► Итог
                          │            │          │             │
                          │            │          │             └─ FileOpFinished в журнал, обновление панелей
                          │            │          └─ по элементам; прогресс; конфликты и ошибки → вопросы пользователю
                          │            └─ потоковый обход источников (подсчёт объёма идёт параллельно с копированием)
                          └─ назначение не внутри источника, источник ≠ назначение, есть права, достаточно места (по возможности)
```

- операция — фоновая задача `tokio` с `CancellationToken` и каналом прогресса;
- прогресс приходит в главный цикл не чаще 10 раз в секунду;
- окно прогресса в стиле Far (текущий файл, общий объём, скорость, оставшееся время); можно свернуть в фон (`Esc` → «Продолжить в фоне») — задача видна в строке состояния и в списке задач;
- несколько операций могут идти одновременно; настройка `ops.serialize_per_volume` ставит в очередь операции на одном физическом томе.

### Копирование

- **Windows:** `CopyFileExW` с колбэком прогресса и флагом отмены. Сохраняет атрибуты, время и альтернативные потоки данных (ADS); для SMB делает копирование на стороне сервера. Для очень больших файлов — флаг `COPY_FILE_NO_BUFFERING` (порог настраивается).
- **Linux/macOS:** `copy_file_range` / `fcopyfile` через `std::fs::copy` для файлов без прогресса; для больших файлов — копирование блоками (1–8 МБ) с прогрессом; затем права и время.
- запись идёт во временный файл `.<имя>.afar-part` рядом с назначением и в конце атомарно переименовывается — прерванное копирование не оставляет полуфайл под настоящим именем (режим отключаемый: на некоторых сетевых ФС переименование дорогое);
- символические ссылки: настройка «копировать как ссылки» (по умолчанию) / «копировать содержимое».

### Перемещение

- тот же том → `rename` (мгновенно, атомарно);
- другой том → копирование + проверка (размер, по настройке — хеш) + удаление источника **только после успешного копирования каждого элемента**;
- переименование на месте (`Shift+F6`) — частный случай.

### Удаление

- по умолчанию — в корзину (крейт `trash`); `Shift+Del` — безвозвратно (с отдельным подтверждением);
- рекурсивное удаление **никогда не проходит по символическим ссылкам и junction'ам** — удаляется сама ссылка, а не её цель (на этом ошибались многие файловые менеджеры);
- файлы с атрибутом «только чтение» — вопрос, как в Far (удалить / все / пропустить / отмена);
- удаление корня диска, домашнего или системного каталога — дополнительное подтверждение с вводом подтверждения, независимо от источника команды.

### Конфликты (файл в назначении уже существует)

Вопрос пользователю (как в Far): *Заменить / Пропустить / Переименовать / Дописать / Заменить, если новее*, с флажком «Применить ко всем». В вопросе — размеры и даты обоих файлов. Для операций агента политика конфликтов передаётся параметром (`on_conflict`: `ask` (по умолчанию) / `skip` / `overwrite_if_newer` / `rename`); `overwrite` агенту доступен только через подтверждение пользователя.

### Ошибки

Ошибка на элементе → вопрос: *Повторить / Пропустить / Пропустить все / Отмена*. Текст — системное сообщение плюс путь. Для операций агента без живого пользователя (тайм-аут вопроса) — пропуск с записью в итог.

Итог операции содержит число обработанных элементов, объём, список ошибок (путь + текст) и признак «отменено пользователем». Он целиком попадает в `FileOpFinished`.

### Проверки, которые нельзя пропустить

| Проверка | Как |
|---|---|
| Назначение внутри источника (копирование папки в саму себя) | сравнение канонических путей + `file_id` |
| Источник и назначение — один и тот же файл (в том числе через другой регистр букв, жёсткую ссылку, подстановку диска) | сравнение `file_id` |
| Длинные пути (> 260 символов) на Windows | стандартная библиотека Rust добавляет префикс `\\?\`; при прямых вызовах WinAPI — добавлять его явно |
| Имена, недопустимые на целевой ФС (`CON`, `aux.txt`, `:` и т. п.) | проверка до операции, вопрос пользователю |
| Нехватка места | предварительная оценка, если известен общий объём; при ошибке «нет места» — обычный вопрос об ошибке |

## Слежение за ФС

- `notify` следит за каталогами, открытыми в панелях (не рекурсивно);
- изменение → перечитывание панели с сохранением курсора и выделения (как в Far);
- изменения, вызванные операциями afar, отфильтровываются по таблице «недавно затронутых путей»; остальные идут в журнал как `FsChanged` с атрибуцией (агент / внешнее) — см. [02-architecture.md](02-architecture.md#журнал-событий).

## Тестовая матрица (`afar-ops`)

- копирование и перемещение файлов и деревьев внутри тома и между томами (на CI — два временных каталога + RAM-диск, если доступен);
- все варианты конфликтов, включая «применить ко всем»;
- отмена в середине файла и в середине дерева: нет полуфайлов, источник при перемещении не тронут;
- символические ссылки, junction'ы, ссылки на каталоги внутри удаляемого дерева (цель ссылки должна уцелеть);
- файлы только для чтения, файлы без прав доступа, заблокированные файлы (Windows);
- длинные пути, Unicode-имена, имена с пробелами и точками в конце;
- копирование файла в самого себя и папки в свою подпапку — отказ до начала операции.
