# 04. Агент

## Модель интеграции

Агент — настоящий `claude` (Claude Code CLI), запущенный во встроенном терминале в панели агента. afar **не перехватывает** интерфейс Claude Code и не реализует цикл агента. Связь двусторонняя и идёт по трём каналам:

```
                 ┌──────────────────────────── afar ────────────────────────────┐
                 │                                                               │
 пользователь ──►│ панель агента = PTY-сессия ──── stdin/stdout ────► claude     │
                 │                                                     │  │  │  │
                 │ MCP-сервер (127.0.0.1, токен) ◄── инструменты afar_* ┘  │  │  │
                 │                                                         │  │  │
                 │ /hook/* (тот же сервер) ◄── `afar hook …` ◄── хуки ─────┘  │  │
                 │                                                            │  │
                 │ слежение за ФС ◄────────── собственные правки агента ──────┘  │
                 └───────────────────────────────────────────────────────────────┘
```

1. **Терминал**: пользователь общается с агентом в привычном интерфейсе Claude Code.
2. **MCP**: агент читает состояние afar и журнал, управляет панелями, просмотрщиком, файловыми операциями.
3. **Хуки Claude Code**: afar подмешивает журнал в запросы пользователя (режим live) и узнаёт о собственных действиях агента (правки файлов, команды).

Ни глобальные настройки пользователя (`~/.claude`), ни файлы проекта при этом не меняются: всё передаётся параметрами запуска.

## Запуск сессии

При старте afar (или при первом переходе в панель агента — настройка `agent.autostart`) создаётся каталог сессии и запускается:

```
claude --mcp-config   <session>/mcp.json
       --settings     <session>/settings.json
       --append-system-prompt "<текст из <session>/system-prompt.md>"
```

> Флаги и формат хуков сверить с актуальной версией Claude Code при реализации (`claude --help`, документация по hooks) — это внешний интерфейс, он может меняться.

- рабочий каталог — каталог активной панели на момент запуска (настройка: или фиксированный корень проекта);
- окружение дополняется `AFAR_ENDPOINT=http://127.0.0.1:<port>`, `AFAR_TOKEN=<токен>`, `AFAR_SESSION=<id>` — их наследуют хуки, которые запускает `claude`;
- размер PTY = размер панели агента; при изменении высоты панели вызывается `resize`.

`<session>/mcp.json`:

```json
{
  "mcpServers": {
    "afar": {
      "type": "http",
      "url": "http://127.0.0.1:53817/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

`<session>/settings.json` (только хуки; остальные настройки Claude Code пользователя действуют как обычно):

```json
{
  "hooks": {
    "SessionStart":     [{ "hooks": [{ "type": "command", "command": "\"C:/Tools/afar/afar.exe\" hook session-start" }] }],
    "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "\"C:/Tools/afar/afar.exe\" hook user-prompt" }] }],
    "PostToolUse": [{
      "matcher": "Edit|MultiEdit|Write|NotebookEdit|Bash",
      "hooks": [{ "type": "command", "command": "\"C:/Tools/afar/afar.exe\" hook post-tool" }]
    }]
  }
}
```

Путь к `afar.exe` подставляется абсолютный (текущий исполняемый файл).

Жизненный цикл:
- завершение `claude` → заголовок панели «завершён: код N», `Enter` в панели — перезапуск;
- команды: `agent.restart`, `agent.restart_here` (в каталоге активной панели), `agent.continue` (перезапуск с `--continue`);
- при выходе из afar с живой сессией — подтверждение.

## Журнал для агента

### Формат выдачи

Компактный текст — экономия токенов и удобство чтения моделью:

```
[afar journal #38–#44 | left: C:\proj\src | right: D:\backup | focus: left]
#38 14:01:52 user  cd     left  C:\proj → C:\proj\core
#39 14:01:58 user  select left  3 files: util.rs, fmt.rs, io.rs
#40 14:02:05 user  move   3 items → C:\proj\src            ok
#41 14:02:30 user  cmd    cargo build  (cwd C:\proj)        exit 101, 2.3s  [output: cmd-17]
#42 14:03:10 agent edit   C:\proj\src\lib.rs
#43 14:03:12 ext   change C:\proj\target\…  (37 files)
#44 14:03:40 user  view   C:\proj\src\lib.rs
```

- большие серии сворачиваются (`(37 files)`);
- вывод команд по умолчанию не включается — только ссылка `[output: cmd-17]` и размер; исключение — команды с ненулевым кодом возврата: к ним прикладываются последние строки вывода (см. [«Консольный вывод»](#консольный-вывод));
- ограничение на объём одной порции (по умолчанию ~60 записей / 4 тыс. символов); если событий больше — последние записи плюс строка `… ещё 120 событий, используйте afar_journal(since=…)`.

### Режимы наблюдения

| Режим | Индикатор | Что происходит |
|---|---|---|
| **live** | `● live` | С каждым запросом пользователя хук `UserPromptSubmit` вызывает `afar hook user-prompt`, тот получает от afar порцию журнала с момента прошлой передачи и печатает её в stdout. Claude Code добавляет этот вывод в контекст запроса. Агент «видит всё сразу» |
| **on-demand** (по умолчанию) | `○` | Журнал копится. Хук передаёт только однострочную сводку: `[afar: 7 новых событий с #38, используйте afar_journal]`. Агент читает журнал инструментом, когда сочтёт нужным |
| **пауза** | `‖` | Журнал не пишется (приватные действия). Агенту при следующем запросе — `[afar: журнал был приостановлен 14:05–14:12]` |

Переключение: команда `agent.observe_mode` (меню, клавиша в настройке), флаг сохраняется в конфигурации.

Хук `SessionStart` сразу передаёт агенту краткую справку о среде: пути обеих панелей, фокус, режим наблюдения, номер последнего события.

> Агент получает новые события **в момент запроса пользователя**, а не непрерывно: Claude Code — диалоговый агент, а постоянная доставка событий без запроса тратила бы токены впустую.

## Консольный вывод

Вывод команд, запущенных из командной строки afar (аналог «экрана пользователя» Far, `Ctrl+O`), — один из главных источников контекста для агента: ошибки сборки, упавшие тесты, сообщения утилит.

### Как выполняются команды

- Каждая команда — **отдельный процесс в отдельной PTY со своим эмулятором** (`cmd /c …` / `pwsh -Command …` / `sh -c …`). «Экран пользователя» составляется из текста завершённых команд и живого экрана текущей. Пользователь видит непрерывную ленту, как в Far, а afar точно знает границы каждой команды: время начала и конца, код возврата, её вывод.
  - Общий эмулятор для всех команд не годится — проверено в прототипе: ConPTY перерисовывает экран по собственной копии и затирает вывод предыдущих команд.
- Тот же механизм используется для `afar_run_command` — команды агента видны пользователю в той же ленте, с пометкой.
- Команды, запущенные в отдельном окне (`Shift+Enter`), и внешние программы, открытые по ассоциации, не захватываются: в журнале — `CommandStarted` с пометкой `detached`, без вывода.

### Как захватывается текст

Не «сырой» поток байтов (в нём полосы прогресса через `\r`, перемещения курсора, цвета — после удаления VT-последовательностей получается мусор и мегабайты повторов), а **результат работы эмулятора терминала**:

1. Строки, уходящие из видимой области эмулятора в историю прокрутки, дописываются в `sessions/<id>/output/<cmd_id>.log` как готовый текст — ровно то, что видел пользователь. Полоса прогресса, перерисованная тысячу раз, становится одной (последней) строкой.
2. При завершении команды дописываются оставшиеся строки видимой области.
3. **Полноэкранные программы** (включают альтернативный экран, `?1049h`: `vim`, `htop`, `less`, `far`) — построчный вывод из них не пишется; сохраняется снимок экрана в момент выхода из альтернативного экрана и пометка `[полноэкранная программа: N с]`.
4. Ограничения: до 5 МБ текста на команду (настройка `journal.output_max_bytes`); при превышении сохраняются первые 1000 и последние строки, в середине — маркер пропуска. Маски `journal.redact` применяются и к выводу.
5. Ввод пользователя в интерактивную программу отдельно не записывается — попадает в лог только то, что программа отобразила на экране (пароли, вводимые без эха, не сохраняются).

### Что получает агент

| Ситуация | Что видит агент |
|---|---|
| Режим live, команда завершилась с кодом 0 | строка журнала со ссылкой `[output: cmd-17, 340 строк]` |
| Режим live, код возврата ≠ 0 | строка журнала + последние 30 строк вывода (настройка `agent.live_output_tail_on_error`) |
| Режим on-demand | только сводка; вывод — по запросу инструментом |
| Команда ещё выполняется | `afar_state` показывает её в «выполняемых»; `afar_command_output` отдаёт вывод на текущий момент; `afar_terminal_screen` — текущий видимый экран (например, вопрос, на котором программа ждёт ответа) |

Вывод собственных команд агента (инструмент Bash самого Claude Code) агент и так получает напрямую — дублировать не нужно; в журнал попадает только факт выполнения (через хук `PostToolUse`).

## Действия агента через afar (MCP-инструменты)

Все инструменты превращаются в `Invocation { origin: Agent }` и проходят через тот же слой команд и ту же политику, что и действия пользователя. Каждое действие видно в интерфейсе и записывается в журнал с `actor = agent`.

### Чтение состояния

| Инструмент | Параметры | Результат |
|---|---|---|
| `afar_state` | — | обе панели (путь, файл под курсором, число выделенных + первые имена, сортировка, вид), фокус, открытые просмотрщики, фоновые задачи, выполняемая команда, режим наблюдения, последний `seq` |
| `afar_panel_list` | `side`, `offset?`, `limit?`, `selected_only?` | элементы панели: имя, тип, размер, дата, атрибуты, выделен ли |
| `afar_journal` | `since?`, `limit?`, `kinds?`, `actor?` | записи журнала в формате выше |
| `afar_commands` | `limit?`, `status?` (`running`/`failed`/`all`) | список недавних команд: `cmd_id`, текст, каталог, код возврата, длительность, число строк вывода |
| `afar_command_output` | `cmd_id` (или `last`), `tail_lines?`, `head_lines?`, `range?`, `grep?` | текст вывода команды (в том числе выполняющейся); строки пронумерованы, чтобы ссылаться на них в следующих запросах |
| `afar_terminal_screen` | — | текущий видимый экран терминала пользователя как текст (для работающих интерактивных программ) |
| `afar_tasks` | `task_id?` | фоновые операции: тип, прогресс, ошибки |

### Показать пользователю

| Инструмент | Параметры | Поведение |
|---|---|---|
| `afar_navigate` | `side`, `path`, `cursor?` | перейти в каталог, поставить курсор на файл |
| `afar_select` | `side`, `names?` / `mask?`, `mode`: `set`/`add`/`remove` | выделить файлы |
| `afar_focus` | `side` | сделать панель активной |
| `afar_view` | `path`, `line?`, `search?` | открыть во встроенном просмотрщике на строке |
| `afar_edit` | `path`, `line?` | открыть в редакторе |
| `afar_highlight` | `paths[]`, `note?`, `ttl_s?` | временно подсветить файлы в панелях и показать заметку в строке состояния |
| `afar_notify` | `text`, `level` | ненавязчивое уведомление (не диалог) |

### Действовать

| Инструмент | Политика по умолчанию | Поведение |
|---|---|---|
| `afar_mkdir` | разрешено | создать каталог(и) |
| `afar_copy` / `afar_move` | подтверждение | открывается диалог F5/F6 с заполненными полями и пометкой «Запрошено агентом»; выполнение — движком afar с прогрессом; возвращается `task_id`, итог — в журнале и через `afar_tasks` |
| `afar_rename` | подтверждение | переименование |
| `afar_delete` | подтверждение, только в корзину | `permanent=true` разрешается только настройкой |
| `afar_run_command` | подтверждение | команда выполняется в сессии оболочки (видна пользователю в режиме терминала); возвращается `cmd_id` |

Подтверждения не блокируют агента: вызов MCP ждёт ответа пользователя (с тайм-аутом, по умолчанию 5 минут) и возвращает `approved` / `rejected` / `modified` (если пользователь поменял параметры в диалоге).

### «Агент показывает — пользователь подтверждает»

Рекомендуемый агенту стиль для массовых операций (сценарий С3 в [01-vision.md](01-vision.md#с3-разложи-по-папкам)): создать папки → выделить группу файлов `afar_select` → предложить `afar_move` → пользователь видит выделение в панели и подтверждает. Этот стиль описывается в дополнении к системному промпту.

## Действия агента своими средствами

Агент может читать/править файлы и запускать команды собственными инструментами Claude Code (Read, Edit, Write, Bash) — afar этому не мешает. Чтобы эти действия не были невидимыми:

1. Хук `PostToolUse` (matcher `Edit|MultiEdit|Write|NotebookEdit|Bash`) вызывает `afar hook post-tool`; тот читает JSON со stdin (`tool_name`, `tool_input`, `tool_response`) и отправляет в afar краткую сводку: инструмент, затронутые пути, для Bash — команду и код возврата.
2. afar пишет `AgentToolUsed` в журнал, обновляет панели, если затронуты показанные каталоги, и подсвечивает изменённые файлы (цвет «изменено агентом» до следующей смены каталога или N минут).
3. Изменения ФС, которые заметил watcher и которые совпадают с путями из `AgentToolUsed`, атрибутируются агенту, а не помечаются как внешние.

## Дополнение к системному промпту

Короткий текст (~20 строк), передаётся через `--append-system-prompt`:

- ты работаешь внутри файлового менеджера afar; пользователь видит две файловые панели над тобой;
- инструменты `afar_*` показывают пользователю результат в интерфейсе — используй `afar_view`/`afar_navigate`, когда ссылаешься на файл или место в коде;
- журнал действий пользователя доступен через `afar_journal`; в режиме live он приходит в запросе блоком `[afar journal …]`;
- для массовых файловых операций предпочитай «выдели → предложи операцию через afar», а не Bash;
- разрушительные операции через afar требуют подтверждения пользователя — это нормально, не обходи их через Bash.

## Безопасность

- MCP- и hook-эндпоинты слушают только `127.0.0.1`, порт случайный, токен — 256 бит, новый на каждую сессию; файлы сессии (`mcp.json`, `settings.json`) создаются с правами только для текущего пользователя.
- Запросы без токена или с чужим токеном отклоняются; токен не пишется в журнал и логи.
- Политика разрешений для `Origin::Agent` применяется в слое команд, а не в MCP-обработчиках, — обойти её через другой инструмент нельзя.
- Журнал может содержать чувствительные данные (имена файлов, текст команд): настройка `journal.redact` — маски команд/путей, которые не записываются (например, `*password*`, `*.kdbx`); режим «пауза».
- Разрешения самого Claude Code (что агент может делать своими инструментами) afar не меняет — они настраиваются пользователем в Claude Code как обычно.

## Другие агенты

MCP-сервер и журнал не привязаны к Claude Code. В панели агента можно запустить любой CLI-агент с поддержкой MCP (настройка `agent.command` и шаблон его MCP-конфигурации). Режим live и атрибуция правок требуют хуков; для агентов без хуков доступен только режим on-demand.

## Развитие: структурированный режим

Альтернативная «морда» для той же связки — вместо терминала свой виджет чата поверх `claude -p --input-format stream-json --output-format stream-json`:

- плюсы: сообщения и вызовы инструментов рисуются средствами afar (пути кликабельны, правки — диффом в просмотрщике), запросы разрешений Claude Code — диалогами afar (через `--permission-prompt-tool`), журнал подмешивается без хуков;
- минусы: пропадают интерактивные возможности интерфейса Claude Code, свой виджет чата (markdown, прокрутка, ввод) нужно писать.

MCP-сервер, журнал и слой команд одинаковы для обоих режимов, поэтому решение можно принять после прототипа. Это этап M5+.
