# История строк ввода и автозавершение в Far: исследование для повторения

Собрано из исходников Far Manager 3 (`../FarManager/far`, BSD-3-Clause). Ссылки вида `history.cpp:148` указывают на эти исходники. Строки интерфейса даны идентификатором `lng::M…` и текстом «русский / английский» из `farlang.templ.m4`; `&` обозначает горячую букву. Цвета записаны в обозначениях консоли Windows (`F_WHITE|B_CYAN` — белый на бирюзовом). Если что-то выведено только из кода и не проверено в работающем Far, это сказано явно.

## 2. Хранилище

**Четыре вида истории** (`history.hpp:57–63`): `HISTORYTYPE_CMD` (команды), `HISTORYTYPE_FOLDER` (папки), `HISTORYTYPE_VIEW` (просмотр и редактор), `HISTORYTYPE_DIALOG` (строки ввода диалогов). У диалоговой истории есть **имя** (`key`): у каждого поля свой список, а поля с одинаковым именем делят один список (см. §3). У остальных видов имя пустое.

**Таблица** — одна на все виды, в базе `history.db` профиля (`configdb.cpp:2836`):

```sql
history(id INTEGER PRIMARY KEY, kind INTEGER, key TEXT, type INTEGER, lock INTEGER,
        name TEXT, time INTEGER, guid TEXT, file TEXT, data TEXT)      -- configdb.cpp:1966
```

`kind` — вид истории, `key` — имя списка, `name` — сама строка, `time` — время в сотнях наносекунд, `lock` — закрепление. `type`, `guid`, `file` и `data` нужны истории папок и просмотра (`HR_VIEWER`, `HR_EDITOR`, `HR_EDITOR_RO`, `HR_EXTERNAL`, плагин и его данные). В истории команд в `data` хранится текущая папка, где команду запустили (`cmdline.cpp:502`).

**Добавление** (`History::AddToHistory`, `history.cpp:148–196`).
- Пустая строка не записывается ни в одну историю, кроме диалоговой (156). Поэтому пустое значение поля **попадает** в историю диалога.
- **Повторы.** Ищется запись с тем же `name` без учёта регистра (`name COLLATE NOCASE = ?`), тем же `type`, `guid` и `file`; у не-командных историй сравнивается ещё и `data` (165–187). Найденная запись удаляется, новая добавляется с текущим временем, то есть строка поднимается наверх. **Закрепление наследуется** (`Lock = Lock || i.Lock`, 181). Регистр берётся у нового ввода.
- После добавления позиция перебора сбрасывается (`ResetPosition`, 195).
- Не пишется во время выполнения макроса, если макрос отключил историю (153). `suppressor()` временно запрещает запись: так работает Shift+Enter в истории папок.

**Закрепление (lock).** Ins в любом меню истории переключает флаг (`FlipLock`, 493–504). Закреплённая запись помечена галочкой (`set_check`, 310). Её не удаляют ни Shift+Del, ни Del («очистить всё» удаляет только незакреплённые, `stmtDelUnlocked`), ни Ctrl+R, ни сжатие.

**Лимиты и сжатие** (`History::CompactHistory`, 133–146; вызывается только при выходе из Far, `ctrlobj.cpp:128`).

| Параметр far:config | Умолчание | Что ограничивает |
|---|---|---|
| `History.CommandHistory.Count` / `.Lifetime` | 1000 / 90 дней | команды |
| `History.DialogHistory.Count` / `.Lifetime` | 1000 / 90 | каждый список диалога отдельно |
| `History.FolderHistory.Count` / `.Lifetime` | 1000 / 90 | папки |
| `History.ViewEditHistory.Count` / `.Lifetime` | 1000 / 90 | просмотр и редактор |

(`config.cpp:2022–2029`.) Запрос `stmtDeleteOldUnlocked` (`configdb.cpp:1992`) удаляет незакреплённые записи, которые **одновременно** старше `Lifetime` дней и не входят в `Count` самых новых (сортировка `lock DESC, time DESC`). Значит, `Count` — это не жёсткий потолок: за 90 дней список может вырасти больше 1000. Списки диалогов обрабатываются, только если в них больше `Count` записей (`stmtEnumLargeHistories`, 1993). Во время работы размер списков не ограничивается.

**Сохранять или нет** (`History::HistoryCfgRef`, 778–781). У каждой истории есть трёхпозиционная настройка (`Bool3Option`):
- выключено — история ведётся в базе **в памяти** (`HistoryCfgMem`): работает до выхода из Far и не сохраняется;
- включено — постоянная база;
- третье состояние — постоянная база плюс «белый список» записей (85–121, 783–818): видны записи, сделанные до запуска этого экземпляра Far, и собственные записи. Записи других одновременно запущенных экземпляров не видны. Это выведено из кода, в справке третье состояние не описано.

Настройки: `System.SaveHistory` (команды), `System.SaveFoldersHistory`, `System.SaveViewHistory` — все по умолчанию true (`config.cpp:2193–2195`, флажки `MConfigSaveHistory` и др. в «Системных параметрах», 188–190); `Dialog.EditHistory` — true (1983, флажок в «Настройках диалогов»).

- **Общие списки.** `Masks` делят выделение по маске, маска поиска файла и маски ассоциаций. `SearchText` делят поиск файла, просмотрщик и редактор. `LineNumber` общий у просмотрщика и редактора.

- Плагины задают историю тем же флагом и могут менять её сообщениями `DM_SETHISTORY` и `DM_ADDHISTORY` (`dialog.cpp:5053–5090`).

## 4. Поле с историей в диалоге

**Стрелка.** Справа от поля, в столбце `right+1`, рисуется `↓` цветом `COL_DIALOGTEXT` (`F_BLACK|B_LIGHTGRAY`; в диалоге-предупреждении `COL_WARNDIALOGTEXT`; у недоступного поля `COL_DIALOGDISABLED`) (`dialog.cpp:1970–1974`, цвета 1425–1460). Стрелка видна, только если у поля есть история и включено `Dialogs.EditHistory` (`ItemHasDropDownArrow`, 1188–1191). Щелчок по стрелке открывает список (3314–3325). Попадание мышью в поле считается с учётом этого столбца (3268).

**Начальное значение (`DIF_USELASTHISTORY`).** Если поле при создании **пустое**, в него подставляется самая новая запись списка по времени, без учёта закрепления (`ProcessLastHistory`, 1003–1019; `LastItem` → `stmtGetNewest`). Если код диалога уже положил в поле значение (например, путь другой панели у F5), история не используется. Обычный текст в поле считается «неизменённым» (`SetClearFlag`): он выделен, и первый введённый символ его заменяет (`dialog.cpp:858–945`).

**Когда пишется в историю** (`Dialog::CloseDialog`, `dialog.cpp:4178–4187`):
- при закрытии с `ExitCode >= 0`, то есть при нажатии **любой кнопки**, включая «Отмена». Esc и закрытие по `-1` историю не пишут. Так написано в коде; на живом Far поведение с кнопкой «Отмена» не проверялось;
- только для полей с `DIF_HISTORY`, непустым именем истории и без `DIF_MANUALADDHISTORY`;
- скрытое поле (`DIF_HIDDEN`) пишется, только если его текст меняли;
- пишется итоговый текст поля (`strData`), до раскрытия переменных `DIF_EDITEXPAND`; пустая строка тоже записывается;
- `DIF_MANUALADDHISTORY` — автоматической записи нет, владелец диалога сам вызывает `DM_ADDHISTORY` (5084–5090). В ядре Far этот флаг не используется (только плагинами).

**Открыть список** (`dialog.cpp:2753–2759` → `ProcessOpenComboBox`, 3459–3482):
- **Ctrl+Up** / **Ctrl+Down** (также Ctrl+Numpad8 / Ctrl+Numpad2, с левым или правым Ctrl);
- колесо мыши, когда фокус на поле ввода (стоит в том же `case`; по коду, не проверено);
- щелчок по стрелке `↓`.

Список не открывается у поля только для чтения (`DIF_READONLY`), при выключенной `Dialogs.EditHistory` и если в списке нет записей (`ProcessMenu` сразу возвращает `HRT_CANCEL`, `history.cpp:246–247, 331–332`). Alt+Down **не** открывает список: такого случая в `Dialog::ProcessKey` нет.

## 5. Выпадающий список истории диалога

**Вид** (`Dialog::SelectFromEditHistory`, `dialog.cpp:3894–3931`).
- `VMenu2` с флагами `VMENU_ALWAYSSCROLLBAR | VMENU_COMBOBOX | VMENU_SHOWAMPERSAND`, рамка `SHORT_SINGLE_BOX` (одинарная), **без заголовка**, без тени, не перемещается.
- **Положение** (`Dialog::CalcComboBoxPos`, 5997–6030). По горизонтали — от левого до правого края поля; если поле уже 21 столбца, правый край расширяется до `left+20`. Видно не больше `Dialogs.CBoxMaxHeight` пунктов (умолчание **8**, `config.cpp:1981`), высота = пункты + 2 строки рамки. Список открывается **под** полем, если снизу хватает места или снизу места больше, чем сверху; иначе **над** полем.
- **Порядок** (`history.cpp:274`, `stmtEnumDesc`): сначала закреплённые, затем самые новые сверху (`ORDER BY lock DESC, time DESC`). Курсор стоит на первом пункте. В отличие от Alt+F8, здесь новые записи сверху.
- Перед первой записью каждого нового дня вставляется разделитель с датой (`time_point_to_localtime_string`, 295–303). Это общий код для всех видов истории, поэтому даты есть и в списке диалога (по коду). Закреплённые записи помечены галочкой. `&` в тексте показывается как есть.
- **Цвета** — палитра комбинированного списка `COL_DIALOGCOMBO*` (`vmenu.cpp:3252–3268`): текст и рамка `F_WHITE|B_CYAN`, выбранный пункт `F_WHITE|B_BLACK`, полоса прокрутки `F_WHITE|B_CYAN`, стрелки `F_YELLOW|B_CYAN`, «серый» `F_DARKGRAY|B_CYAN` (`palette.cpp:154–201`). В диалоге-предупреждении — `COL_WARNDIALOGCOMBO*`, по умолчанию те же цвета.

**Клавиши в списке** (`History::ProcessMenu`, 349–548, плюс обычные клавиши меню):

| Клавиша | Действие |
|---|---|
| Up / Down / PgUp / PgDn / Home / End, колесо | движение по списку, без перехода через край (`VMENU_WRAPMODE` у этого списка не задан, в отличие от Alt+F8 и списка автозавершения) |
| **Enter**, щелчок по пункту | подставить запись в поле, `LeftPos=0`, текст больше не «неизменённый» (`dialog.cpp:3920–3927`). Диалог не закрывается |
| **Tab** | то же, что Enter (только для диалоговой истории, 352–356) |
| Esc | закрыть, поле не меняется |
| **Ins** / Numpad0 | закрепить / открепить запись (493–504) |
| **Shift+Del** | удалить текущую запись, если она не закреплена (505–520) |
| **Del** | очистить весь список, кроме закреплённых. Если включено `Confirm.HistoryClear` (умолчание true, `config.cpp:1966`), сначала спрашивается: заголовок `MHistoryTitle`, текст `MHistoryClear`, кнопки `MClear` / `MCancel` (521–542) |
| **Ctrl+C**, Ctrl+Ins | скопировать запись в буфер обмена, список не закрывается (478–491) |
| Shift+Enter, Ctrl+Enter, Ctrl+Shift+Enter, Ctrl+Alt+Enter, F3, F4, Ctrl+R | в списке диалога **поглощаются** без действия (430–431, 445–475) |
| буквы | горячих букв нет (`VMENU_SHOWAMPERSAND`); RAlt или Ctrl+Alt+F включает фильтр меню, как в любом меню Far |

## 6. Перебор похожих: Ctrl+End

- **Командная строка** (`cmdline.cpp:275–296`). Если курсор в конце строки, Ctrl+End (и Ctrl+Numpad1) заменяет строку самой новой командой истории, которая начинается с введённого текста (без учёта регистра и не равна ему). Дописанная часть выделяется. Повторный Ctrl+End берёт следующую подходящую команду, старше предыдущей, и ходит по кругу (`History::GetSimilar`, `history.cpp:695–746`, `CyclicGetPrev`). Префикс запоминается в `strLastCmdStr` / `LastCmdPartLength` и сбрасывается любой другой клавишей (598).
- **Поле диалога** (`dialog.cpp:2998–3018`). Работает так же, но по истории поля. Условие проверяется уже после того, как поле обработало Ctrl+End, поэтому перебор срабатывает всегда, а не только когда курсор был в конце. Сброс — `LastPartLength=-1` при любой другой клавише (3021).
- Справка (`DialogSettings`) советует Ctrl+End как ручную замену автозавершению, когда оно выключено.

## 7. Другие истории (кратко)

**Команды** (`ctrlobj.cpp:76`, `cmdline.cpp`).
- Запись делается при выполнении непустой команды по Enter / Shift+Enter / Ctrl+Alt+Enter, если `ExcludeCmdHistory` не содержит бит `EXCLUDECMDHISTORY_NOTCMDLINE` (502). Другие биты этого параметра исключают команды из ассоциаций и из запуска с панели.
- **Ctrl+E** — предыдущая (более старая) команда, **Ctrl+X** — следующая (329–339). На самой старой Ctrl+E останавливается. Если пройти Ctrl+X дальше самой новой, возвращается текст, который был в строке до начала перебора (`m_CurCmdStr`, `IsOnTop`). Когда панели скрыты, Up/Down и колесо тоже работают как Ctrl+E/Ctrl+X (300–323).
- **Esc** очищает строку. Позиция в истории сбрасывается, только если `System.CmdHistoryRule=true` (умолчание false, 347–353).
- **Alt+F8** (361–378): меню `MHistoryTitle` «История команд / History», тема справки `History`. Высота `ScrY-8`, меню по центру экрана, `VMENU_WRAPMODE`. Порядок — старые сверху, курсор на самой новой (или на записи, до которой дошли Ctrl+E/Ctrl+X; `history.cpp:313–326`). Цвета обычного меню `COL_MENU*`. Клавиши: Enter — выполнить; Shift+Enter — выполнить в отдельном окне; Ctrl+Alt+Enter — от имени администратора; Ctrl+Enter — вставить в командную строку; F3 — окно `MHistoryInfoTitle` «Информация» с полем `MHistoryInfoFolder` «Папка:» (папка запуска, `history.cpp:456–470`); Ins, Del, Shift+Del и Ctrl+C — как в §5.

**Папки** — Alt+F12 (`cmdline.cpp:426–467`), меню `MFolderHistoryTitle` «История папок», тема `HistoryFolders`. Enter — перейти; Shift+Enter — перейти без записи в историю; Ctrl+Shift+Enter — перейти на пассивной панели; Ctrl+Enter — вставить путь в командную строку; Ctrl+R — удалить несуществующие пути (`history.cpp:365–410`). Курсор запоминается между вызовами (`KeepSelectedPos=true`). Для записи плагина показывается `Плагин:файл:путь`. При выходе из Far в историю пишется текущая папка (`ctrlobj.cpp:123–124`).

**Просмотр и редактор** — Alt+F11, `MViewHistoryTitle`. Подробно — в `12-far-viewer-reference.md` §10.

Если запись папки или файла не существует, Enter выводит сообщение об ошибке, и меню остаётся открытым. Для файла редактора Far предлагает его создать: `MViewHistoryIsCreate` «Создать файл?» (566–596).

## 8. Автозавершение

### 8.1. Где включено

**Командная строка** (`cmdline.cpp:102–120`). `EditControl` создаётся с источниками `EC_COMPLETE_HISTORY | EC_COMPLETE_FILESYSTEM | EC_COMPLETE_PATH | EC_COMPLETE_ENVIRONMENT`. Автоматический режим включается флагом `EC_ENABLEAUTOCOMPLETE` по `CmdLine.AutoComplete` (умолчание true, `config.cpp:1949`), флажок `MConfigCmdlineAutoComplete` в «Настройках командной строки». История — история команд.

**Поле диалога** (`dlgedit.cpp:79–104`).
- `EC_ENABLEAUTOCOMPLETE` ставится, если `Dialogs.AutoComplete` (умолчание true, `config.cpp:1980`), у поля есть `DIF_HISTORY`, `DIF_EDITPATH` или `DIF_EDITPATHEXEC`, это не `DIF_DROPDOWNLIST` и нет `DIF_NOAUTOCOMPLETE`.
- Источники: `DIF_HISTORY` → история поля; `DIF_EDITPATH` → файловая система; `DIF_EDITPATHEXEC` → программы из PATH; **переменные окружения — всегда**.
- У комбинированного списка (`DI_COMBOBOX`) вместо истории используются его пункты (`pList`, `editcontrol.cpp:442–459`).

**Вручную — Ctrl+Space** (`cmdline.cpp:588–592`, `dialog.cpp:2985–2991`): автозавершение временно включается и запускается в ручном режиме (`Manual=true`), даже если автоматический выключен. В диалоге это работает и у полей без флагов: тогда остаются только переменные окружения.

### 8.2. Когда запускается

`EditControl::Changed` (`editcontrol.cpp:110–124`) вызывает `AutoComplete(false, DelBlock)` после **каждого изменения текста** (ввод, вставка, удаление). `AutoCompleteProc` (389–403) работает, только если:
- автозавершение включено (`EC_ENABLEAUTOCOMPLETE`);
- строка непуста;
- нет повторного входа;
- **очередь ввода пуста** (`is_input_queue_empty`, 366–387): при быстрой вставке или эмулированном вводе список не появляется;
- не выполняется макрос (кроме ручного вызова и макроса в самом диалоге).

`DelBlock=true` приходит при удалении: BS, Del, Ctrl+BS, Ctrl+Del, удаление блока (`edit.cpp:971, 1005, 1098, 1269, 2084`). Удаление показывает список, но **не дописывает** первый вариант.

### 8.3. Источники и их порядок (`Complete`, 420–480)

Каждый источник включается своим параметром `Interface.Completion.Use*` с тремя значениями: 1 — всегда (умолчание), 0 — никогда, 2 (третье состояние) — только по Ctrl+Space (`CompletionEnabled`, 415–418; `config.cpp:2059–2062`).

1. **История** (`UseHistory`). Используется **вся строка**, а не последнее слово. Записи, начинающиеся с введённого текста без учёта регистра (`GetAllSimilar`, `history.cpp:748–757`), идут в порядке «закреплённые, затем новые». Закреплённые отмечены галочкой. Если найдено хоть что-то, **заголовок списка** — `MCompletionHistoryTitle` «История». Для комбинированного списка — его пункты, без заголовка.
2. Дальше строка разбирается на префикс и **последний токен** (`ParseStringWithQuotes`, 167–215). При нечётном числе кавычек токен начинается после последней `"`. Иначе токен — хвост после последнего разделителя: пробелы плюс `WordDiv` без символов `":\/%.?-`. Кавычки вокруг токена снимаются. Если токен пуст, остальные источники пропускаются.
3. **Файлы** (`UseFilesystem`, `EC_COMPLETE_FILESYSTEM`; `EnumFiles`, 261–292). Ищется `expand_env(токен)*`. Подходят файлы и папки, у которых длинное имя или короткое 8.3 начинается с части имени из токена. Папки показываются **без** завершающего `\`. Для `\\?\` без разделителя добавляются устройства `\??` и `\GLOBAL??`.
4. **Окружение** (`UseEnvironment`; `EnumEnvironment`, 343–364): `%ИМЯ%` всех переменных, у которых `%ИМЯ%` начинается с токена. Значит, токен должен начинаться с `%`.
5. **Программы** (`UsePath`, `EC_COMPLETE_PATH`; `EnumModules`, 294–341). Только если во **всей строке** нет `\` или `/`. Подходят: команды из `System.Executor.ExcludeCmds` (внутренние команды cmd; умолчание пустое), файлы из каталогов `PATH`, расширение которых есть в `PATHEXT`, и имена из реестра `App Paths`.

У файлов, окружения и программ результат — `префикс + вариант`. Вариант с пробелом берётся в кавычки (`QuoteSpace`), а если пользователь открыл кавычку сам, она закрывается (`EnumWithQuoutes`, 223–259). Внутри источника варианты уникальны и отсортированы (`std::set` с `string_sort::less_t`). Источник с результатами получает подпись `MCompletionFilesTitle` «Файлы» или `MCompletionEnvironmentTitle` «Окружение» (у программ тоже «Файлы»). Если список пуст, подпись становится заголовком, иначе вставляется разделителем. Разделитель вставляется **только один раз** (`AddSeparatorOrSetTitle`, 143–165): у третьего источника подписи уже нет. Это особенность кода.

### 8.4. Показ (518–533)

Список показывается, если вариантов больше одного или единственный вариант отличается от ввода без учёта регистра.

- **Подстановка первого варианта** (`AppendCompletion`, умолчание **false**; `AppendCmd`, 484–516). Если изменение не было удалением и (блоки не постоянные или `ShowList` включён), строка заменяется первым вариантом. Регистр введённой части сохраняется (`cmp_user_data::OriginalCaseStr`). Дописанный хвост **выделяется** от прежней длины до конца. Курсор остаётся на месте.
- **Список** (`ShowList`, умолчание **true**). `VMenu2` без тени, `SHORT_SINGLE_BOX`, `VMENU_WRAPMODE | VMENU_SHOWAMPERSAND`. Первым вставляется **пустой пункт**, означающий исходный ввод, и курсор стоит на нём (528–530).
- **Положение** (`SetMenuPos`, 126–141). Слева — от левого края поля, справа — `max(min(ScrX-2, right), left+20)`. Высота — `min(CBoxMaxHeight=8, пунктов)+1`. Список ставится **под** полем; **над** полем — если снизу не хватает места и поле в нижней половине экрана. Раз поднявшись, список остаётся сверху (`MenuUp`). Так список командной строки открывается вверх.
- **Цвета** — обычное меню `COL_MENU*`: флага `VMENU_COMBOBOX` у этого списка нет (`vmenu.cpp:3221`, 3270–3286). Текст и рамка `F_WHITE|B_CYAN`, выбранный `F_WHITE|B_BLACK`, «серый» `F_DARKGRAY|B_CYAN`. По умолчанию это те же цвета, что у списка истории.
- Пока список открыт, курсор остаётся в поле, и ввод продолжает редактировать строку.

### 8.5. Клавиши при открытом списке (539–753)

| Клавиша | Действие |
|---|---|
| символ, BS, Del | удаляется выделенный (дописанный) хвост, клавиша идёт в поле, список пересчитывается. После символа (не после BS/Del) снова дописывается первый вариант. Если вариантов не осталось, список закрывается (590–623) |
| Up / Down / PgUp / PgDn / Home / End, колесо | движение по списку (с переходом через край). В **немодальном** режиме текст поля сразу становится выбранным вариантом, а пустой пункт возвращает исходный ввод (552–559). В модальном поле не меняется |
| **Ctrl+End**, **Ctrl+Space** | следующий пункт (как Down), «классический перебор» (629–637) |
| **Shift+Del** | удалить выбранную запись **истории**, если она не закреплена (`DeleteIfUnlocked`). Файлы так удалить нельзя (639–661) |
| Left / Right | передаются полю как Ctrl+S / Ctrl+D: курсор двигается, список остаётся. Ctrl+Left/Right/Home тоже идут полю (664–686). Движение курсора снимает выделение хвоста, и дописанный текст **принимается** |
| **Enter**, щелчок по пункту | немодальный режим: список закрывается, **Enter передаётся владельцу**. В командной строке команда выполняется, в диалоге срабатывает кнопка по умолчанию (727–740, 755–767). Модальный режим: Enter выбирает пункт, его текст ставится в поле, Enter дальше не идёт |
| Esc, F10 | закрыть список. Текст остаётся тем, что сейчас в поле: в немодальном режиме — последний выбранный вариант (по коду) |
| Shift, Ctrl, Alt (отдельно), Alt+F9, Alt+стрелки | обрабатывает меню, список остаётся |
| любая другая клавиша (Tab, F-клавиши, Ctrl+Enter, …) | список закрывается, клавиша передаётся владельцу (743–748) |

В модальном режиме (`ModalList`) все сообщения меню, кроме ввода, игнорируются (543–544), поэтому движение по списку текст не меняет.

## 10. Заметки для afar

- **Хранилище.** Достаточно одного файла `%LOCALAPPDATA%\afar\history\dialogs.json` (или общего хранилища с командами) с записями `{list, text, time, locked}`. SQLite не нужен. Правила Far: при повторе (без учёта регистра) старая запись удаляется, новая встаёт наверх и наследует закрепление; пустая строка в диалоговую историю пишется; сжатие (старше 90 дней **и** вне 1000 новых, закреплённые не трогаются) — при выходе. В afar уже есть история команд (`src/app/cmdline.rs`, `commands.txt`, Ctrl+E/Ctrl+X, Ctrl+End) — стоит перевести её на ту же модель (закрепление, папка запуска, время), чтобы Alt+F8 и автозавершение командной строки работали с ней одинаково.
- **Имена списков** брать из Far (`Copy`, `NewFolder`, `Masks`, `SearchText`, `ReplaceText`, `LineNumber`, `NewEdit`, `ApplyCmd`, …): тогда общие списки (маски для Gray+/− и поиска файла, текст поиска для просмотрщика, редактора и поиска файла) получатся сами. В `dialog.rs` у поля уже есть `history: bool` для стрелки — заменить на `history: Option<&'static str>` и флаги `use_last` / `edit_path` / `edit_path_exec` / `no_autocomplete`.
- **Первым делом** (минимум, который виден пользователю):
  1. хранилище и запись при закрытии диалога кнопкой (не по Esc);
  2. `use_last` для F7 (`NewFolder`) и Alt+F8 перехода (`LineNumber`);
  3. выпадающий список по Ctrl+Up/Ctrl+Down и щелчку по `↓`: новые сверху, закреплённые первыми, рамка одинарная, ширина поля (минимум 21), до 8 строк, цвета `COL_DIALOGCOMBO*`; Enter/Tab подставляют, Ins закрепляет, Shift+Del удаляет запись, Del очищает с подтверждением, Ctrl+C копирует;
  4. Ctrl+End в поле — перебор похожих.
- **Автозавершение** — вторым шагом, один компонент для поля диалога и командной строки (как `EditControl`): пересчёт после каждого изменения текста, если нет ожидающего ввода; источники по флагам поля; разбор последнего токена с кавычками; немодальный список с пустым первым пунктом. Умолчания Far: список включён, немодальный, первый вариант **не** дописывается. Enter при открытом списке передаётся владельцу, Esc только закрывает список. Для командной строки список ставится над полем (`MenuUp`). Каталоги PATH и `App Paths` лучше сканировать один раз и держать в кэше: Far перечитывает их при каждом нажатии клавиши.
- Пользователь afar и агент видят одну историю. Если агент открывает диалоги (`afar_copy` и т. п.), его значения тоже попадут в историю. Решить, писать ли их (в Far аналог — `suppressor()` / `DIF_MANUALADDHISTORY`).
- Не проверено на живом Far: запись истории по кнопке «Отмена», даты-разделители в выпадающем списке диалога, открытие списка колесом мыши, текст поля после Esc в немодальном списке. Перед повторением спорных мест стоит сверить их на настоящем Far.
