# Встроенный просмотрщик Far (F3): исследование для повторения

Собрано из исходников Far Manager 3 (`../FarManager/far`, BSD-3-Clause). Ссылки вида `viewer.cpp:1599` указывают на эти исходники. Строки интерфейса даны идентификатором `lng::M…` и текстом «русский / английский» из `farlang.templ.m4`; `&` обозначает горячую букву. Цвета записаны в обозначениях консоли Windows (`F_LIGHTCYAN|B_BLUE` — светло-бирюзовый на синем).

**Из панели** (`filelist.cpp:1784–2085`):
- `F3`, `Numpad5`, `Shift+Numpad5` (Numpad5 превращается в F3, 1800), `Alt+F3`, `Ctrl+Shift+F3`.
- Если курсор на папке (в том числе на `..`), просмотрщик не открывается: вызывается `CountDirSize` и считается размер выделенных папок (1868–1874).
- Ассоциации: F3 сначала пробует `FILETYPE_VIEW`, Alt+F3 — `FILETYPE_ALTVIEW` (`ProcessLocalFileTypes`, 2042–2045). Ctrl+Shift+F3 ассоциации пропускает и всегда открывает встроенный просмотрщик (2047).
- Внешний просмотрщик: `EnableExternal = (F3 && UseExternalViewer) || (Alt+F3 && !UseExternalViewer)`, и только если `strExternalViewer` не пуст (2033–2038). По умолчанию внешнего нет, поэтому F3 и Alt+F3 открывают встроенный.
- Встроенный: `FileViewer::create(имя, EnableSwitch=true, DisableHistory=PluginMode, DisableEdit=PluginMode, -1, PluginData, &ViewList)` (2066). `ViewList` — все **не-папки** панели, текущим отмечен открываемый файл (2053–2064); по нему работают Gray+ и Gray−.
- С панели плагина файл сначала извлекается во временный каталог (`GetFile` с `OPM_VIEW`), просмотрщик удаляет его при закрытии (`SetTempViewName`, 2080; удаление в `viewer.cpp:269–289`).
- `Shift+F3` на панели — это не просмотр, а команды архива (`ProcessHostFile`, 1778–1782).
- `Ctrl+Q` включает или выключает панель быстрого просмотра (`filepanels.cpp:479`).

**Создание окна** (`fileview.cpp:223–296`): окно занимает весь экран `{0,0,ScrX,ScrY}`. Если файл не открылся, окно не создаётся и в историю ничего не пишется (253–259). При успешном открытии файл добавляется в историю просмотра `HR_VIEWER` (261–264) и ещё раз при закрытии (576–577). Окно немодальное (`EnableSwitch`), поэтому видно в списке экранов F12.

## 2. Что открывает и как читает

**Открытие** (`viewer.cpp:422–573`): `CreateFile(FILE_READ_DATA, share read|write|delete, OPEN_EXISTING)` (461). Поэтому другой процесс может писать в файл и удалять его, пока тот открыт (справка: файл удалится после закрытия). При ошибке показывается `OperationFailed`: заголовок `MViewerTitle` «Просмотр / Viewer», текст `MViewerCannotOpenFile` «Ошибка открытия файла / Cannot open the file», имя и системная ошибка, кнопки `MDeleteRetry` «&Повторить» и `MCancel` «Отмена» (470). В быстром просмотре (`Warn=false`) диалога нет: область заливается `COL_VIEWERTEXT`, и в левом верхнем углу цветом `COL_WARNDIALOGTEXT` пишется `MViewerCannotOpenFile` (644–656).

**Папки** просмотрщик не открывает (`CreateFile` без `FILE_FLAG_BACKUP_SEMANTICS` выдаёт ошибку). **Потоки NTFS** (`file:stream`) особо не обрабатываются: путь уходит в `CreateFile` как есть.

**stdin**: только в режиме `far -v -` (`OnlyEditorViewerUsed`, имя `-`). Весь stdin копируется во временный файл с `FILE_FLAG_DELETE_ON_CLOSE`, и показывается этот файл (437–458). В обычной работе каналы не поддерживаются.

**Большие файлы.** Файл никогда не загружается целиком.
- Чтение идёт через `CachedRead` с буфером `max(MaxLineSize·2·64, 64 КБ)`; при умолчании 10000 это 1 280 000 байт (225).
- Посимвольное чтение `vgetc` использует кэш на 64 байта (`viewer.hpp:284–311`, `viewer.cpp:3528–3630`).
- Позиции 64-битные (`long long FilePos/FileSize`).
- Кэш начал строк хранит кольцо из 16000 позиций (`lcache_lines(16*1000)`, 244, `CacheLine` 2216–2294).
- Движение вверх ищет CR/LF назад порциями по 250 байт, не дальше `max_backward_size = min(300000, max(2·MaxLineSize,1024)·32)` байт (246, `Up` 2363–2498).

**Дописываемые файлы (аналог `tail -f`)**.
- `reload_timer` раз в 1 с будит главный цикл, и окно получает `KEY_NONE` (`fileview.cpp:99–144`). Период 1 с действует для дисков FIXED, REMOTE, RAMDISK и для съёмных USB; для CD и прочих таймера нет.
- Таймер работает, только пока окно в фокусе (632–645).
- На `KEY_NONE` выполняется `CheckChanged()`: сравниваются время записи и размер (610–636). Если файл уменьшился, кэши сбрасываются.
- Если `FilePos > FileSize`, выполняется Ctrl+End. Если экран стоял на последней странице, а файл вырос, выполняется Ctrl+End: экран «едет» за концом (1640–1665). Справка: «чтобы следить за дописываемым файлом, нажмите End».

**Кодовые страницы.** Поддерживаются страницы с `MaxCharSize ≤ 2` (`IsCodePageSupported(cp, 2)`, 120–123): все однобайтовые (OEM, ANSI, любые установленные), DBCS (932/936/949/950), UTF-8, UTF-16 LE (1200) и BE (1201). UTF-7 и 4-байтовые (GB18030) не поддерживаются. Порядок выбора при открытии (535–549):
1. Кодовая страница из кэша позиций, если включено `SaveCodepage` или `SavePos` и страница поддерживается (501–506).
2. Иначе `GetFileCodepage(file, Default, &Signature, AutoDetectCodePage)` (`filestr.cpp:494–563`):
   - **BOM** проверяется всегда: `EF BB BF` → UTF-8, `FF FE` → UTF-16LE, `FE FF` → UTF-16BE (`GetUnicodeCpUsingBOM`, 289–311).
   - Если автоопределение выключено, берётся страница по умолчанию.
   - Иначе читаются первые 32768 байт. Корректный UTF-8 с не-ASCII байтами даёт UTF-8. Чистый ASCII идёт дальше по цепочке.
   - Затем по очереди: `IsTextUnicode` (эвристики UTF-16, 313–405), **uchardet / nsUniversalDetector** (`uchardet.cpp:320`), MLang `IMultiLanguage2::DetectInputCodepage` (407–448).
   - Фильтры: `NoAutoDetectCP` (чёрный список или «только избранные») и `NoAutoDetectCJK` (450–491).
   - Если определилась 20127 (US-ASCII), берётся страница по умолчанию (545–556).
3. Страница по умолчанию: `ViOpt.DefaultCodePage`; при значении `CP_DEFAULT` (это умолчание) или неподдерживаемой странице — ANSI системы (`GetDefaultCodePage`, 4167–4173).

**Двоичные файлы.** Если включено `DetectDumpMode` (умолчание — да) и в первых 2048 байтах есть `\0` (для UTF-16 — нулевой `wchar_t`), файл открывается в режиме **дампа** (`isBinaryFile`, 575–596; 555–560). Иначе он открывается в текстовом режиме. Режим из кэша (`SaveViewMode`) важнее.

**Декодирование.** Неверные последовательности заменяются на U+FFFD (`encoding::replace_char`). Нечётный последний байт UTF-16 тоже даёт U+FFFD (3418–3421, 3565–3567). Суррогатные пары UTF-8 отдаются двумя `wchar_t` (3586–3590).

## 3. Режимы и отображение

Три режима: `VMT_TEXT=0`, `VMT_HEX=1`, `VMT_DUMP=2`. Кроме того, есть «базовый» режим `m_DumpTextMode`: к нему F4 возвращает из hex.

**Текст** (`ReadString`, 1161–1340).
- Строка заканчивается на **CR, LF, CRLF, а также CRCRLF** (одна строка). Одиночный CR — тоже перевод строки (формат Mac). `IsEol`: `\r` или `\n` (`string_utils.hpp:49`).
- Табуляция раскрывается до ближайшего кратного `TabSize` (умолчание 8, допустимо 1..512) (1220–1224).
- BOM (U+FEFF) на смещении 0 пропускается (1216–1218).
- `\0` заменяется на `ZeroChar` (по умолчанию `·`), если включено `Visible0x00`; иначе выводится пробелом.
- Остальные управляющие символы C0 выводятся глифами CP437: `☺☻♥♦♣♠•◘○◙♂♀♪♫☼►◄↕‼¶§▬↨↑↓→←∟↔▲▼`, 0x7F — `⌂`, C1 — U+FFFD (`console.cpp:84–140`).
- **Максимальная ширина строки** `MaxLineSize` (умолчание 10000; проверка ограничивает 1000..100000, `config.cpp:1808–1813`, хотя справка пишет «минимум 100»). Более длинная строка режется на несколько экранных строк даже без переноса (1190).
- **Перенос (Wrap, F2).** Строка режется по ширине окна; в этом режиме горизонтальная прокрутка вправо невозможна (352–355).
- **Перенос по словам (Shift+F2).** Разрыв ставится после последнего пробела или символа из `WordDiv` (по умолчанию из настроек редактора) в пределах ширины. Хвостовые пробелы срезаются, ведущие пробелы следующей строки пропускаются (1235–1266).
- Без переноса работает горизонтальная прокрутка `LeftPos` (0..`MaxLineSize`).
- Если включено `ShowArrows` (умолчание — да), поверх крайних символов рисуются стрелки цветом `COL_VIEWERARROWS`: `«` в левом столбце, когда `LeftPos>0` и строка не пуста; `»` в последнем столбце текста, когда строка длиннее видимой части (779–791).
- Двунаправленного текста (RTL) нет. Для полноширинных символов в дампе стоит пометка «BUGBUG broken» (843).

**Дамп** (`ShowDump`, 923–970). Понятия строки нет: экранная строка вмещает `ширина × CharSize` байт (CharSize 2 для UTF-16, иначе 1). CR, LF и TAB выводятся глифами. В UTF-8 и DBCS символ стоит в позиции первого байта, а позиции байтов продолжения заполняются `›` (U+203A, `continue_char`). BOM в UTF-8 показывается как U+FFFD (875). Left и Right в дампе ничего не делают.

**Hex** (`ShowHex`, 972–1094). Строка устроена так:

```
0000000000: 54 68 65 20 71 75 69 63 │ 6B 20 62 72 6F 77 6E 20  The quick brown
```

- Адрес: `{:010X}: `. Каждый байт: `XX `. После каждых 8 байт вставляется `│ `. Затем пробел и символы.
- Символов на строку: столько же, сколько байт; для UTF-16 вдвое меньше.
- Ширина строки при 16 байтах: 11 + 3·16 + 2·1 + 2 + 16 = **79** (`hex_mode_line_width_from_bytes`, 153–157).
- По умолчанию 16 байт в строке, минимум 8. Количество меняется клавишами Alt+←/→ (±1) и Ctrl+Alt+←/→ (до кратного 16) (297–331).
- Выделение подсвечивает только hex-цифры, не символьную часть (1031–1092).
- Если строка шире окна, Left и Right прокручивают её по горизонтали.

**Полоса прокрутки** (`DrawScrollbar`, 1099–1127).
- Включается настройкой `ShowScrollbar` (умолчание — нет) или клавишей Ctrl+S; занимает правый столбец окна, и текст сужается на 1 (598–608).
- Вид: `▲`, поле `░` (BS_X_B0), бегунок `█` (BS_X_DB), `▼` (`interf.cpp:1579–1650`).
- В тексте бегунок считается в байтах (FilePos..конец последней строки из FileSize), в hex и дампе — в строках.
- Цвет `COL_VIEWERSCROLLBAR`. В быстром просмотре полоса рисуется в столбце рамки панели цветом `COL_PANELSCROLLBAR`.

**Строка статуса** (верхняя строка, `FileViewer::ShowStatus`, `fileview.cpp:602–630`). Цвет `COL_VIEWERSTATUS` (чёрный на бирюзовом). Видна при `ShowTitleBar` (умолчание — да) и высоте окна больше 1; переключается Ctrl+Shift+B. Содержимое:

```
<имя файла, слева, дополнено пробелами>│t│1251 │1234567   │Кол 0  │42% │12:34
```

- Хвост строится форматом `"│{режим}│{cp:5.5}│{размер:<10}│{Кол:.3} {LeftPos:<3}│{процент:4}"` (610–617):
  - режим — `t`, `h` или `d` (`"thd"[mode]`);
  - кодовая страница — `ShortReadableCodepageName`: `UTF-8`, `U16LE`, `U16BE`, `UTF-7`, `ANSI` (если это ACP), `OEM` (если OEMCP), иначе номер; ширина ровно 5, выравнивание влево (`codepage.cpp:252–266`);
  - размер файла в байтах без разделителей, ширина 10, влево;
  - `lng::MViewerStatusCol` «Кол / Col» (не больше 3 символов), пробел, `LeftPos` шириной 3;
  - процент — `ToPercent(FilePos, FileSize)` для верха экрана, на последней странице 100; например `42% ` (влево, ширина 4).
- Имя: заголовок (`SetTitle` от плагина) или полный путь, сокращённый `truncate_path` до оставшейся ширины.
- Часы: если `Clock` (умолчание — да) и окно во весь экран, справа резервируется место под часы плюс `│`. Часы рисует `ShowTime` в `ScrX+1-len` цветом `COL_VIEWERCLOCK` (`interf.cpp:649–673`).

**Заголовок консоли**: `Interface.ViewerTitleFormat` = `"%Lng %File"`. `%Lng` заменяется на `lng::MInViewer` «просмотр / view», `%File` — на имя без пути (`fileview.cpp:551–558`).

## 5. Поиск (F7)

Диалог общий с редактором: `GetSearchReplaceString({ShowButtonsPrevNext=true}, …, history "SearchText", help "ViewerSearch")` (`viewer.cpp:3087–3112`, `stddlg.cpp:131–483`). **Логика** (`DoSearchReplace`, 3114–3340):
- Новый поиск идёт вперёд от **начала видимой области** (`BegOfScreen`), назад — от конца экрана (`EndOfScreen(0)`).
- Продолжение (Shift+F7, Space, Alt+F7) идёт от найденного выделения ± 1 символ.
- Регулярные выражения в стиле Perl, без многострочного поиска.
- «Целые слова» используют `WordDiv` + BOM + U+FFFD.
- Hex-поиск ищет байты.
- Не найдено: сообщение-предупреждение «Поиск» с текстом `MViewSearchCannotFind` «Строка не найдена» (или `MViewSearchCannotFindHex` «Байты не найдены») и строкой в кавычках, кнопка `MOk`.
- Достигнут край файла (зависит от far:config `Viewer.SearchWrapStop`, умолчание `BSTATE_CHECKED`): вопрос «Поиск» с текстами `MViewSearchEod` «Достигнут конец документа» + `MViewSearchFromBegin` «Продолжить поиск с начала документа?» (назад — `MViewSearchBod`/`MViewSearchFromEnd`, при проходе точки старта — `MViewSearchCycle` «Просмотрен весь документ» / `MViewSearchRepeat` «Повторить поиск в документе?»), кнопки `MYes` «Да» и `MCancel`.
- Значение `Viewer.SearchWrapStop`: Unchecked — тихо переходить через край; Checked — спрашивать на краю файла; 3-state — спрашивать при проходе точки старта (2567–2570).
- Долгий поиск через некоторое время показывает окно прогресса «Поиск» с текстом `MViewSearchingFor` «Поиск» / `MViewSearchingHex` «Поиск байтов» + строка и процентом. Esc прерывает с подтверждением `MKeyESCWasPressed` «Действие было прервано» (3270–3307).
- **Найденное** становится выделением (`SelectPos/SelectSize`) цвета `COL_VIEWERSELECTEDTEXT` (чёрный на бирюзовом).
- Если найденное уже на экране, позиция не меняется. Иначе строка с ним ставится на четверть экрана от верха (`(ScrY − (ShowKeyBar?2:1))/4`, 3327–3333).
- Без переноса `LeftPos` подбирается так, чтобы совпадение было видно с запасом 10 столбцов (3852–3864, 744–762).

## 6. Переход (Alt+F8)

`GoToRowCol` (`stddlg.cpp:1081–1109`) построен через `DialogBuilder`. Заголовок `MGoTo` «Перейти / Go to», тема справки `ViewerGotoPos`. Состав:
- поле ввода шириной 28 (история `LineNumber`, фокус, последняя запись истории);
- разделитель;
- `[ ] MGoToHex` «16-ричное &значение / &Hex value»;
- OK/Отмена.

Флажок Hex при первом вызове в окне равен «режим hex», дальше запоминается в окне (`m_GotoHex`, `viewer.cpp:3722–3725`).

**Формат ввода** (`GetRowCol`, 997–1079): `[+|-]значение[%]`, затем, через разделитель из `" .,;:"`, необязательный второй элемент — столбец.
- Префикс `+`/`-` делает значение относительным.
- Суффикс `%` означает процент от размера файла.
- Шестнадцатеричное: префикс `0x` или `$`, суффикс `h`, либо флажок Hex. Суффикс `m` принудительно задаёт десятичное.
- При флажке Hex процент всё равно десятичный.

**Смысл значений:** первое значение — **смещение в байтах** (не номер строки). После него `AdjustFilePos` выравнивает позицию к началу строки, в которой лежит смещение (`GoTo` 3714–3764, `AdjustFilePos` 3766–3807). Второе значение — первый видимый столбец (`LeftPos`), только для текста без переноса. Особенность: относительный столбец умножается на `Row.relative` (3741–3742), так что `+N` для столбца без относительной строки не сработает. Пустой элемент не меняет соответствующий параметр.

## 10. История и кэш позиций

**Alt+F11** — `ShowViewEditHistory` (`cmdline.cpp:869`).
- Меню `MViewHistoryTitle` «История просмотра и редактирования», тема `HistoryViews`. Строки вида `Просмотр: путь` (`MHistoryView`), `Редактор: путь`, `Редактор:-путь` (только чтение), `Внешний: …`, с разделителями-датами (`history.cpp:257–290`).
- Enter открывает файл. Shift+Enter открывает без записи в историю. F3/F4 (и Numpad5) открывают в просмотрщике/редакторе. Ctrl+Enter вставляет путь в командную строку.
- Ins — закрепить запись. Shift+Del — удалить запись. Del — очистить всё после вопроса `MHistoryClear` с кнопками `MClear` «&Очистить» / `MCancel`. Ctrl+C/Ctrl+Ins — копировать путь (`history.cpp:418–540`).
- Хранится 1000 записей, 90 дней (`ViewEditHistory.Count/Lifetime`, `config.cpp:2028–2029`). Пишется, если `System.SaveViewHistory` (умолчание true).

**Кэш позиций** (`poscache.hpp:98–116`, `poscache.cpp:129–200`, база `HistoryCfg`).
- Ключ — полный путь; для файлов плагина — `PluginData + имя` (`<HostFile:CurDir>имя`).
- Хранится: `FilePos` (байтовое смещение верха экрана), `LeftPos`, `CodePage`, `ViewModeAndWrapState` и 10 закладок `{FilePos, LeftPos}` (`POS_NONE=-1` — пусто).
- Биты `ViewModeAndWrapState`: `0x0F` — режим (0 текст, 1 hex, 2 дамп), `0x10` — «режим менялся в этой сессии», `0x20` — перенос, `0x40` — перенос по словам (`viewer.cpp:103–118`). Режим и перенос записываются только если пользователь их трогал (`monitored<>::touched`, 404–406), и восстанавливаются только при флаге `0x10`.
- Запись: при закрытии и перед Gray+/− (`SavePosition`, 394–413). Чтение: в `OpenFile` (488–533), позиция затем выравнивается к началу строки.

## 11. Прочее

**Быстрый просмотр (Ctrl+Q, `qview.cpp`).**
- Панель с двойной рамкой. Заголовок `MQuickViewTitle` «Быстрый просмотр».
- `Viewer` занимает `{left+1, top+1, right−1, bottom−3}`, без строки статуса (`SetStatusMode(0)`).
- На строке `bottom−2` разделитель, по центру — тип файла из оболочки Windows (`COL_PANELSELECTEDINFO`). На `bottom−1` — имя файла (109–160, 438–455).
- Для папки вместо содержимого выводится `MListFolder` «Папка "путь"» и сводка `MQuickViewFolders` «Папок:», `MQuickViewFiles` «Файлов:», `MQuickViewBytes` «Размер файлов:», `MQuickViewAllocated` «Выделенный размер:», `MQuickViewCluster` «Размер кластера:», `MQuickViewSlack` «Остатки кластеров:», `MQuickViewMFTOverhead` «Занято MFT:» (202–255).
- Клавиши (287–351): F3/Numpad5 открывают полноценный просмотр (F3 другой панели); Gray+/− двигают курсор другой панели; **правый Ctrl+0…9 — ярлыки папок**, а не закладки. Остальные клавиши (код ≥ 256) уходят во `Viewer`.
- Строка клавиш — блок `MQViewF1…`: F3 `MQViewF3` «Просм/View», F9 «ConfMn», Shift+F9 «Save», Shift+F10 «Last», Alt+F1/F2 «Left/Right», Alt+F10 «Tree», Alt+F12 «FoldHs».
- Перенос в быстром просмотре запоминается отдельно (static `LastWrapMode/LastWrapType`, 85–96, 472–487).

**Несколько окон.**
- Каждый просмотр — отдельное окно. В F12 оно показано как `MScreensView` «Просмотр» + полный путь (`GetTypeAndName`, `fileview.cpp:543–548`).
- Один и тот же файл можно открыть дважды.
- Временный файл плагина удаляется, только когда закрыто последнее окно с этим именем (`viewer.cpp:269`).

**События плагинов**: `VE_READ` после открытия, `VE_CLOSE`, `VE_GOTFOCUS`/`VE_KILLFOCUS`. API `ViewerControl` (3882) позволяет плагину задать позицию, выделение, режим и т. д. Макросостояние — `MCODE_V_VIEWERSTATE` (1504–1516).

**Заметки для afar.**
- Модель — «верх экрана = байтовое смещение» (`FilePos`), а не номер строки. Процент, Alt+F8, закладки и кэш позиций работают в байтах. Строки находятся сканированием вперёд и назад вокруг смещения, поэтому файл любого размера открывается мгновенно.
- Смена кодировки, переноса или режима всегда вызывает `AdjustFilePos`: позиция выравнивается к началу строки или символа.
- Hex-режим с 16 байтами занимает 79 столбцов, поэтому при полосе прокрутки на 80 колонках умещается ровно.
