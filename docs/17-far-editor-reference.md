# Встроенный редактор Far (F4): исследование для повторения

Собрано из исходников Far Manager 3 (`../FarManager/far`, BSD-3-Clause), в том же порядке, что и [12-far-viewer-reference.md](12-far-viewer-reference.md). Ссылки вида `editor.cpp:1599` указывают на эти исходники. Строки интерфейса даны идентификатором `lng::M…` и текстом «русский / английский» из `farlang.templ.m4`; `&` обозначает горячую букву. Цвета записаны в обозначениях консоли Windows (`F_LIGHTCYAN|B_BLUE` — светло-бирюзовый на синем). Справка Far: темы `@Editor`, `@EditorSearch`, `@FileOpenCreate`, `@FileSaveAs`, `@EditorGotoPos`, `@EditorReload`, `@EditorSettings` и `@Editor.*` в `FarRus.hlf.m4`. Где поведение выведено только из кода и не проверено на живом Far, это сказано явно.

## 1. Файлы и точки входа

| Файл | Что в нём |
|---|---|
| `editor.hpp/.cpp` | `class Editor`: текст как список строк, клавиши, мышь, блоки (потоковые и вертикальные), отмена, поиск и замена, «найти всё», переход, закладки, отрисовка текста, номера строк, полоса прокрутки. Тот же класс работает в диалогах как `DI_MEMOEDIT` (`FEDITOR_DIALOGMEMOEDIT`, `editor.hpp:345`) |
| `fileedit.hpp/.cpp` | `class FileEditor`: окно на весь экран, загрузка и сохранение, кодовые страницы, строка статуса, строка клавиш, F2/Shift+F2/F4/F6/F10/Esc/Shift+F10, диалоги «Открыть/создать» и «Сохранить как», кэш позиций |
| `edit.hpp/.cpp` | `class Edit`: одна строка — текст, курсор, выделение, конец строки, табуляция, отрисовка строки и пробельных символов. Общий с полями ввода диалогов |

| `stddlg.cpp` | диалог поиска/замены `GetSearchReplaceString` (131–483), переход `GoToRowCol` (1081–1109) и разбор ввода `GetRowCol` (997–1079) |
| `filestr.cpp` | разбиение файла на строки `enum_lines` (67–223), определение кодовой страницы `GetFileCodepage` (289–311, 494–563) |
| `eol.cpp` | типы концов строк `none / win / unix / mac / bad_win` (`eol.cpp:46–51`) |

**Из панели** (`filelist.cpp:1784–2015`):
- `F4`, `Alt+F4`, `Shift+F4`, `Ctrl+Shift+F4`.
- F4 на папке (в том числе на `..`) редактор не открывает, а вызывает диалог атрибутов — так же, как `Ctrl+A` (1866–1871).
- Ассоциации: F4 сначала пробует `FILETYPE_EDIT`, Alt+F4 — `FILETYPE_ALTEDIT` (`ProcessLocalFileTypes`, 1951). `Ctrl+Shift+F4` ассоциации и внешний редактор пропускает: всегда встроенный (1957).
- Внешний редактор: `(F4 или Shift+F4) && UseExternalEditor` либо `Alt+F4 && !UseExternalEditor`, и только если `strExternalEditor` не пуст (1943–1944). По умолчанию внешнего нет, поэтому F4 и Alt+F4 открывают встроенный.
- Встроенный: `FileEditor::create(имя, CP_DEFAULT, (Shift+F4 ? FFILEEDIT_CANNEWFILE : 0) | FFILEEDIT_ENABLEF6)` (1993). В окно передаётся список не-папок панели (`SetNamesList`, 1998–2007), но сам редактор по нему не ходит (в отличие от Gray+/− просмотрщика); список нужен только для F6 → просмотрщик.
- С панели плагина файл сначала извлекается во временный каталог (`GetFile` с `OPM_EDIT`), редактор открывается **модально** с `FFILEEDIT_DISABLEHISTORY` и `PluginData`; после закрытия, если файл сохраняли (`WasFileSaved`), он возвращается плагину через `PutFiles(OPM_EDIT)` (1966–1990, 2012–2027).

**Shift+F4 — открыть или создать** (`dlgOpenEditor`, `fileedit.cpp:155–185`). Диалог 76×10, рамка (3,1)–(72,8), заголовок `MEditTitle` «Редактор / Editor», тема справки `FileOpenCreate`:
- y=2: `MEditOpenCreateLabel` «&Открыть/создать файл: / &Open/create file:»;
- y=3: поле (5..70) с историей `NewEdit`, последняя запись подставляется (`DIF_USELASTHISTORY`), переменные окружения раскрываются;
- y=5: `MEditCodePage` «&Кодовая страница: / &Code page:» и выпадающий список (25..70). В начале списка `MDefaultCP` «По умолчанию / Default» (`CP_DEFAULT`) и `MEditOpenAutoDetect` «Автоматическое определение / Automatic detection» (`CP_REDETECT`), затем страницы (`codepage_selection.cpp:325–331`);
- y=7: `MOk` / `MCancel`.

Если папки из введённого пути нет, показывается предупреждение `MWarning`: `MEditNewPath1` «Путь к редактируемому файлу не существует,» / `MEditNewPath2` «но будет создан при сохранении файла.» / `MEditNewPath3` «Продолжать?», кнопки `MHYes` «&Да» / `MHNo` «&Нет» (`filelist.cpp:1840–1858`).

**Пустое имя** (Shift+F4 и Enter без имени): создаётся новый файл с именем `MNewFileName` «Новый_файл_{гггг}-{мм}-{дд}_{чч}.{мм}.{сс}.{мсс}.txt / New_File_….txt» в текущем каталоге (`SetFileName`, `fileedit.cpp:2148–2162`), и включается `FFILEEDIT_SAVETOSAVEAS`: F2 работает как Shift+F2 (549, 1985).

**Из просмотрщика F6** (`fileview.cpp:464–494`): сначала проверяется, что файл открывается на чтение (иначе `OperationFailed` с `MEditCannotOpen` «Ошибка открытия файла / Cannot open the file»). Редактор создаётся с той же кодовой страницей, `StartLine = -2` и `StartChar = FilePos` (байтовое смещение верха экрана просмотрщика) и **заменяет** окно просмотра (`Update`).

**Прочие входы**: `far -e[строка[:позиция]] файл` (`main.cpp:187`, флаги `CANNEWFILE | ENABLEF6`); история Alt+F11 (`cmdline.cpp:893–900`, запись «только чтение» открывает с `FFILEEDIT_LOCKED`); найденный файл в Alt+F7 (модально, `findfile.cpp:1966–1976`); описание в информационной панели (`infolist.cpp:752, 764`); редактирование пользовательского меню (`usermenu.cpp:731`); API плагинов `Editor()` (`plugapi.cpp:1832, 1898`).

**Создание окна** (`FileEditor::Init`, `fileedit.cpp:523–841`):
- Окно занимает весь экран `{0,0,ScrX,ScrY}` (`create`, 421–429). Без `FFILEEDIT_ENABLEF6` окно модальное (`ExecuteWindow`), с ним — обычное (`InsertWindow`/`ReplaceWindow`, 830–839).
- **Папка** (например, введённая в Shift+F4): `MEditCanNotEditDirectory` «Невозможно редактировать папку / It is impossible to edit the folder», кнопка `MOk` (716–727).
- **Только для чтения.** Если в `Editor.ReadOnlyLock` взведён бит 1 и у файла есть R/O (биты 5 и 6 добавляют Hidden и System), спрашивается: имя, `MEditRSH` «предназначен только для чтения / is a read-only file», `MEditROOpen` «Вы хотите редактировать его? / Do you wish to edit it?», кнопки `MYes`/`MNo`; «Нет» — окно не открывается (729–744). Бит 0 переключает режим блокировки (как Ctrl+L) при загрузке (`LoadFile`, 1525–1528). Именно переключает (`Invert`), так что файл, открытый из истории как «только чтение» и одновременно попавший под бит 0, окажется разблокирован — выведено из кода. По умолчанию `ReadOnlyLock = 0`: R/O-файлы открываются без вопросов и без блокировки.
- **Файл уже открыт в другом окне редактора** (`FindWindowByFile`, 563–699). Если то окно изменено (`GetCanLoseFocus(true)` = false, 2101–2109) или включено подтверждение `Confirm.AllowReedit` (`MSetConfirmAllowReedit` «Повто&рное открытие файла в редакторе», умолчание — да, `config.cpp:1957`), задаётся вопрос: заголовок `MEditTitle`, текст — полный путь и `MAskReload` «уже загружен. Как открыть этот файл? / already loaded. How to open this file?», кнопки `MCurrent` «&Текущий» (переключиться в открытое окно), `MNewOpen` «&Новая копия» (второе окно на тот же файл), `MReload` «Пере&грузить» (старое окно закрывается **без сохранения и без записи позиции**, файл читается заново), `MCancel`. Для модального редактора есть только «Новая копия» и «Отмена». Если подтверждение выключено и старое окно не изменено, Far молча переключается в него. Тема справки `EditorReload`.
- **Новый файл**: файла нет на диске → `FFILEEDIT_NEW`; подпись `m_bAddSignature` берётся из `Editor.AddUnicodeBOM` (754–761).
- Успешно открытый файл добавляется в историю просмотра `HR_EDITOR` (или `HR_EDITOR_RO`, если включена блокировка) (806–807), повторно — при Ctrl+L (1283–1293) и при закрытии (`OnDestroy`, 2085–2088).
- В F12 окно показано как `MScreensEdit` «Редактор / Edit» + полный путь (`GetTypeAndName`, 2060–2065), со звёздочкой `*`, если изменено (`manager.cpp:467`).
- Первые 500 мс после открытия F4 игнорируется, чтобы автоповтор F4 из панели не закрыл окно (`f4_key_timer`, 114–130, 986–992).

## 2. Чтение и сохранение

**Открытие** (`LoadFile`, `fileedit.cpp:1440–1708`):
- `CreateFile(FILE_READ_DATA, share read [| write], OPEN_EXISTING, FILE_FLAG_SEQUENTIAL_SCAN)` (1450). `FILE_SHARE_WRITE` добавляется при `Editor.EditOpenedForWrite` (`MEditShareWrite` «Разрешить редактирование открытых для записи &файлов», умолчание — да). Без него файл, который другой процесс держит открытым на запись, не откроется: «Ошибка открытия файла» + системная ошибка, кнопки «Повторить»/«Отмена» (776–779).
- После чтения файл **закрывается** (1671). Во время редактирования Far его не держит: другие программы могут писать и удалять его.
- **Ограничение размера** `Editor.FileSizeLimit` (байты, умолчание 0 — не проверять, только far:config). Если размер больше: имя, `MEditFileLong` «имеет размер {0},», `MEditFileLong2` «что превышает заданное ограничение в {0}.», `MEditROOpen` «Вы хотите редактировать его?», кнопки `MYes`/`MNo` (1463–1489). Если размер не удалось узнать — `MEditFileGetSizeError` «Не удалось определить размер.» (1493–1510).
- Файл всегда читается **целиком** в память. Если чтение длится дольше порога `time_check`, появляется окно прогресса `MEditTitle` / `MEditReading` «Чтение файла {0}» с процентом; Esc прерывает с подтверждением (`CheckForEscAndConfirmAbort`) (1613–1642).

**Кодовая страница при открытии** (1530–1555). Поддерживаются те же страницы, что и в просмотрщике (`IsCodePageSupported`).
1. Явно заданная (Shift+F4, F6 из просмотрщика, плагин).
2. Иначе (`CP_DEFAULT`) — из кэша позиций, если она там есть и поддерживается.
3. Иначе `GetFileCodepage(файл, по умолчанию, &BOM, AutoDetectCodePage)`: BOM (`EF BB BF`, `FF FE`, `FE FF`) проверяется всегда; затем, если включено автоопределение (умолчание — да): первые 32768 байт, корректный UTF-8 → UTF-8, иначе эвристики (`IsTextUnicode`, uchardet, MLang) — подробно в [12-far-viewer-reference.md](12-far-viewer-reference.md) §2 (`filestr.cpp:494–563`). Определённая 20127 (US-ASCII) заменяется страницей по умолчанию.
4. Страница по умолчанию — `Editor.DefaultCodePage`; при `CP_DEFAULT` (это умолчание) или неподдерживаемой — `encoding::codepage::ansi()`. Комментарий: именно «ansi», а не «real_ansi», чтобы при системной UTF-8 редактор тоже открывал в UTF-8 (`GetDefaultCodePage`, 2785–2791).
5. `CP_REDETECT` (пункт «Автоматическое определение» в Shift+F4 или Shift+F8) — то же определение, но без кэша и с эвристиками независимо от настройки (1535–1547).

**BOM.**
- Если страница определялась по файлу, BOM пропускается сдвигом указателя файла (`GetUnicodeCpUsingBOM`, `filestr.cpp:289–311`), а флаг `m_bAddSignature` запоминает, что он был.
- Если страница была задана или взята из кэша и это UTF-8/UTF-16, ведущий U+FEFF первой строки срезается и тоже ставит флаг (1603–1610).
- При сохранении BOM пишется по этому флагу; в «Сохранить как» его можно сменить (§2, «Сохранить как»).

**Ошибки декодирования.** Если в байтах встретилась последовательность, недопустимая в выбранной странице, показывается `BadCodepageDialog` (194–269), стиль предупреждения, заголовок `MWarning` «Предупреждение»:
- текст `MUnsupportedCodePageSelectedCodepage` «Выбранная кодовая страница»;
- список страниц;
- `MUnsupportedCodePageDoesNotSupport` «не поддерживает {0}» с подстановкой `MUnsupportedCodePageByteSequence` «последовательность байтов» и самими байтами;
- `MEditorSaveNotRecommended` «Сохранять файл не рекомендуется.»;
- кнопки `MOk`/`MCancel`.

Выбор другой страницы перечитывает файл с начала. Та же страница → файл открывается с U+FFFD на месте ошибок, взводится `BadConversion` (1578–1601). Перед сохранением такого файла Far ещё раз предупреждает: `MEditDataLostWarn` «Во время редактирования файла некоторые данные были утеряны.» + `MEditorSaveNotRecommended`, кнопки `MEditorSave` «Сохранить» / `MCancel` (1826–1842). Кодовая страница файла с `BadConversion` в кэш не пишется (2714).

**Концы строк** (`enum_lines::GetTString`, `filestr.cpp:137–223`; `eol.cpp:46–51`):
- Признаются `LF` (unix), `CR LF` (win), `CR CR LF` (bad_win — след двойного текстового преобразования, одна строка), одиночный `CR` (mac).
- `CR CR` без `LF` даёт две строки с концом mac.
- Конец строки хранится **у каждой строки отдельно** — в трёх битах флагов `Edit` (`FEDITLINE_EOL_DATA0..2`, `edit.hpp:80–85`). Смешанные концы строк сохраняются как были.
- `GlobalEOL` — первый встреченный в файле конец строки. Если концов нет вовсе, берётся `GetDefaultEOL()`: CRLF, или LF при `Editor.NewFileUnixEOL` (только far:config, умолчание — нет) (1644–1647, 1668–1669; `editor.cpp:134–137`).
- У последней строки конца нет. Если файл кончается переводом строки, в конце добавляется пустая строка без конца (1665–1666), поэтому файл из `N` строк с завершающим `\n` показывается как `N+1` строка.
- `\0` и прочие управляющие символы хранятся в строке как есть. Выводятся через общий слой консоли — тот же, что в просмотрщике (12-far-viewer-reference.md §2); на живом Far для редактора не проверялось.

**Новая строка (Enter)** получает конец текущей строки. Если у текущей конца не было (последняя строка), ей ставится `GlobalEOL`, а новая наследует «нет конца» (`editor.cpp:3098–3106, 3130`).

**Вставка из буфера** с переводами строк (`Paste`, `editor.cpp:4240–4349`). При `Editor.KeepEditorEOL` (умолчание — да) строки получают конец строки, стоящей **перед** курсором (4270–4278). Иначе — свой конец из буфера: `\r\n`, `\n`, `\r` или `\r\r\n` (4291–4308).

**Смена кодовой страницы в открытом файле** (`SetCodePageEx`, `fileedit.cpp:1309–1375`; F8 и Shift+F8):
- Обычно — **без перечитывания**: каждая строка переводится в байты старой страницы и декодируется новой (`Editor::SetCodePage`, `editor.cpp:7084–7114`). Это **переинтерпретация байтов**, а не перекодирование текста: при сохранении на диск уйдут те же байты. Перекодировать текст — это «Сохранить как» с другой страницей.
- Перед этим `TryCodePage` (7036–7082) проверяет, что все строки переводятся. Если нет — предупреждение `MWarning`: «Выбранная кодовая страница», имя страницы, «не поддерживает {0}» («cимвол» / «последовательность байтов» + данные), `MEditorSwitchCPConfirm` «Продолжить?», кнопки `MEditorSaveCPWarnShow` «Показать» (курсор встаёт на ошибку), `MOk`, `MCancel` (`fileedit.cpp:2719–2764`).
- **С перечитыванием файла** — если старая или новая страница UTF-16 либо был `BadConversion` (и файл не новый). Несохранённые правки при этом теряются: сначала спрашивается `MEditorReloadCPWarnLost1` «Для смены кодовой страницы требуется перезагрузка файла.» / `MEditorReloadCPWarnLost2` «Все несохранённые изменения будут потеряны.», `MOk`/`MCancel` (1342–1364).
- Неподдерживаемая страница: `MEditorCPNotSupported` «Кодовая страница {0} не поддерживается вашей системой» (1326–1335).

**Сохранение F2** (`SaveAction`, 1979–2041; `SaveFile`, 1752–1977). F2 пишет файл **всегда**, даже без изменений. Вместо F2 открывается «Сохранить как», если стоит `SAVETOSAVEAS` (новый безымянный файл, файл из архива в Alt+F7), `EPHEMERAL` (результаты «найти всё») или нет родительской папки (1983–1986). Порядок проверок в `SaveFile`:
1. **Файл изменён снаружи.** Сравниваются время записи и размер с запомненными при открытии или прошлом сохранении (`FileInfo`). Если отличаются: `MEditAskSaveExt` «Файл был изменён внешней программой. Сохранить? / The file was changed by an external program. Save?», кнопки `MHYes` «&Да», `MEditBtnSaveAs` «Сохр&анить как…», `MHCancel` «&Отмена», тема `WarnEditorSavedEx` (1757–1784). **Другой проверки изменений на диске нет**: ни таймера, ни проверки при получении фокуса, ни вопроса «перечитать?». Перечитать можно только повторным открытием (F4 → «Перегрузить»).
2. **Только для чтения**: имя, `MEditRO` «имеет атрибут "Только для чтения"», `MEditOvr` «Вы хотите перезаписать его?», `MYes`/`MNo`. «Да» снимает R/O перед записью (1786–1804). Атрибуты исходного файла (`FileAttr`, вместе с R/O) затем передаются в `save_file_with_replace` и после записи выставляются снова (`file_io.cpp:84, 150–157`) — вывод из кода.
3. **Файла нет** — недостающие папки пути создаются (`CreatePath`, 1806–1824).
4. Предупреждение о `BadConversion` (выше).
5. Новый конец строки из «Сохранить как» становится `GlobalEOL` (1844–1847).
6. Для не-UTF страниц каждая строка и её конец проверяются на кодируемость. При ошибке — `BadCodepageDialog(false)` с кнопками `MEditorSaveCPWarnShow` «Показать» (курсор на первый непереводимый символ), `MEditorSave` «Сохранить» (можно сменить страницу в списке), `MCancel` (1858–1905).
7. Событие плагинам `EE_SAVE` (1907–1909).
8. Запись (`file_io.cpp:59–158`). При `Editor.SaveSafely` (умолчание — да) пишется временный файл в той же папке, затем `ReplaceFileW`. Исключения, где пишется прямо в файл (`TRUNCATE_EXISTING`): поток NTFS (`:` в имени), reparse-точка, жёсткие ссылки > 1. При `Editor.CreateBackups` (умолчание — нет, только far:config) `ReplaceFileW` оставляет `имя.bak`; без временного файла резервной копии нет. Время создания исходного файла переносится на временный (134–140). Ошибка записи — `OperationFailed` с `MEditCannotSave` «Ошибка сохранения файла», «Повторить»/«Отмена» (`fileedit.cpp:2029–2032`).
9. Каждая строка пишется со своим концом. Если в «Сохранить как» выбран другой формат, всем строкам, у которых конец был, он **заменяется в памяти** (1946–1950). Пока сохранение не завершено, после порога появляется прогресс `MEditSaving` «Сохранение файла {0}»; Esc его не прерывает (1935–1941).
10. После записи: флаг «изменён» снимается, запоминается позиция отмены `UndoSavePos` (§7), ставятся `WAS_SAVED` и `NEWUNDO`, снимаются `NEW`, `DELETEONCLOSE` и `EPHEMERAL`, перечитываются время, размер и атрибуты (1856, 1915–1967).

## 3. Модель текста

- **Строки**: `std::list<Edit>` (`editor.hpp:156, 348`), итераторы с номером строки (`numbered_iterator`, 165–196). Указатели: верх экрана `m_it_TopScreen`, текущая строка `m_it_CurLine`, начало блока `m_it_AnyBlockStart`, последнее найденное `m_FoundLine`. Строк всегда не меньше одной (`editor.cpp:161`, `fileedit.cpp:1517–1520`).
- **Строка** `Edit`: текст `m_Str` (UTF-16, `wchar_t`), курсор `m_CurPos` (индекс символа, может быть больше длины), выделение `m_SelStart`/`m_SelEnd` (`-1` в конце означает «до конца строки вместе с переводом строки»), `LeftPos`, конец строки во флагах (`edit.hpp:255–270`).
- **Позиции**: «реальная» (индекс в строке) и «экранная» (столбец). Переводит `RealPosToVisual`/`VisualPosToReal` с учётом табуляции, а при включённой ширине символов — и широких символов (`edit.cpp:1931–1943`, `interf.cpp:1371`). Суррогатные пары курсор проходит целиком (`edit.cpp:1177–1201`). Статус показывает оба числа (§8).
- **Табуляция**: `TabSize` 1..512, умолчание 8 (`config.cpp:1800–1805`). Режим `ExpandTabs`:
  - 0 — не преобразовывать;
  - 1 — новые Tab вставляются пробелами до следующей позиции табуляции (`InsertTab`, `edit.cpp:1846–1870`);
  - 2 — все Tab превращаются в пробелы. Это происходит при каждой установке и вставке строки (`edit.cpp:1698–1699, 1784–1785`), то есть уже при загрузке файла, и необратимо (`editor.cpp:6776–6797`). Позиции в этом режиме считаются с шагом табуляции 1.
  - Tab в режиме замены (Ins) только двигает курсор к следующей позиции табуляции (`edit.cpp:1453–1460`). Shift+Tab сдвигает курсор назад к предыдущей позиции табуляции, не удаляя текста (1384–1395).
- **Длинные строки**: переноса нет. Горизонтальная прокрутка общая для всех строк экрана (`LeftPos` текущей строки раздаётся остальным, `editor.cpp:320–333`). Прокрутка минимальная — курсор держится у края (`FixLeftPos`, `edit.cpp:2272–2283`); BS у левого края сдвигает окно на 15 столбцов (946–952). Ограничения длины строки нет.
- **Курсор за концом строки** (`EditorCursorBeyondEOL`, `MEditCursorBeyondEnd` «Ку&рсор за пределами строки», умолчание — **да**).
  - Курсор свободно ходит правее текста. Ввод символа там дополняет строку пробелами до курсора (`edit.cpp:1517–1520`). Если строка пуста, вместо пробелов копируется отступ ближайшей непустой строки выше — табуляция и пробелы (`editor.cpp:2531–2580`).
  - Если выключено: курсор прижимается к концу строки (`editor.cpp:279–297`); при движении вверх и вниз запоминается желаемый столбец (`MaxRightPosState`, 1688–1701); Right в конце строки переходит в начало следующей (2506–2522).
- **Автоотступ** (`AutoIndent`, `MEditConfigAutoIndent` «Авто&отступ», умолчание — нет). Enter ставит курсор на отступ ближайшей непустой строки выше, повторяя её пробельные символы. Хвостовые пробелы строки, разрезанной Enter'ом в «пустом» хвосте, срезаются (`InsertString`, `editor.cpp:3029–3051, 3077–3080, 3135–3210`). При вставке из буфера автоотступ работает только для первого символа (4268–4337).
- **Режим замены** (Ins): флаг `FEDITOR_OVERTYPE`. Виден только по форме курсора (`Interface.CursorSize`, `edit.cpp:152–160`), в статусе не показывается.
- **Блокировка** (Ctrl+L, `FEDITOR_LOCKMODE`): все правки игнорируются, движение, поиск и копирование работают. В статусе — `-` (`fileedit.cpp:2301`).
- **Блоки** (`editor.hpp:314–318`):
  - *Потоковый* (`BTYPE_STREAM`): у каждой строки свой `SelStart..SelEnd`, начало — `m_it_AnyBlockStart`. Конец блока — первая строка без выделения. Выделение «за концом строки» закрашивается до правого края окна (`edit.cpp:457–475`).
  - *Вертикальный* (`BTYPE_COLUMN`): прямоугольник в экранных столбцах `VBlockX`, `VBlockSizeX`, `VBlockSizeY` от строки `m_it_AnyBlockStart`. Рисуется поверх текста, включая места за концом строк (`editor.cpp:360–389`). В буфер обмена копируется построчно, короткие строки дополняются пробелами до ширины блока (`VBlock2Text`, 5369–5406). Помечается форматами `FAR_VerticalBlock_Unicode`, `MSDEVColumnSelect`, `Borland IDE Block Type`; Ctrl+V с любым из них вставляет столбцом (`platform.clipboard.cpp:307–330, 635–655`; `VPaste`, `editor.cpp:5408–5504`).
  - **Постоянные блоки** (`PersistentBlocks`, `MEditConfigPersistentBlocks` «&Постоянные блоки», в редакторе умолчание — **нет**, в просмотрщике — да). Без них клавиши движения (`is_clear_selection_key`: стрелки, Home/End, PgUp/PgDn, Ctrl+стрелки, Ctrl+Home/End/PgUp/PgDn, Ctrl+N/E/S, `editor.cpp:801–821`, `edit.cpp:2368–2384`), щелчок мыши, переход, закладки снимают выделение. Ввод символа, Enter, вставка заменяют потоковый блок (`editor.cpp:2463–2475, 1839–1840, 4247–4248`). С ними эти клавиши лишь заканчивают пометку (следующий Shift+стрелка начнёт новый блок), а Enter её тоже заканчивает (`KeysP`, 815–820).
  - Вставленный текст становится выделением (`Paste`, 4261, 4338). Без постоянных блоков оно тут же снимается (1503–1504), с ними — остаётся.
  - **Del удаляет блоки** (`DelRemovesBlocks`, `MEditConfigDelRemovesBlocks` «Del удаляет б&локи», умолчание — да): Del при любом выделении удаляет блок (1549–1550). BS при `Editor.BSLikeDel` (только far:config, умолчание — да) ведёт себя так же, иначе удаляет только непостоянный потоковый блок (1625–1637).
  - Пустой (нулевой ширины) блок снимается автоматически (`UnmarkEmptyBlock`, 4623–4657).
- **Разделители слов** (`Editor.WordDiv`, умолчание ``~!%^&*()+|{}:"<>?`-=\[];',./``, `config.cpp:110, 2020`; пустое значение заменяется умолчанием, 1818) плюс пробел и табуляция (`iswblank`). Используются в Ctrl+←/→, Ctrl+Shift+←/→, Ctrl+BS, Ctrl+Del, двойном щелчке, «целых словах» поиска и кнопке «Слово» в диалоге поиска.

**Логика** (`DoSearchReplace`, `editor.cpp:3647–4128`):
- Поиск идёт **от курсора**, а не от верха экрана, как в просмотрщике. Продолжение (Shift+F7, Alt+F7) сдвигается на символ, только если курсор стоит там, где его оставил прошлый поиск (начало или конец найденного). Иначе это новый поиск от курсора (`CalculateSearchStartPosition`, 3384–3431).
- Поиск **построчный**: регулярное выражение не находит переводы строк и многострочные конструкции. Строка, начинающаяся с `/`, компилируется в стиле Perl (`/шаблон/флаги`); без «Учитывать регистр» — `OP_IGNORECASE`. Ошибка компиляции показывается `ReCompileErrorMessage` (3673–3687).
- «Целые слова» используют `WordDiv` редактора (3745).
- **Через край файла поиск не переходит**: дойдя до конца (или начала при поиске назад), он останавливается. Вопроса «продолжить с начала» и аналога `Viewer.SearchWrapStop` нет (3988–4009).
- Не найдено: предупреждение «Поиск» с `MEditNotFound` «Строка не найдена / Could not find the string» и строкой в кавычках, кнопка `MOk` (4120–4127).
- Долгий поиск через некоторое время показывает прогресс «Поиск» / `MEditSearchingFor` «Искать {0}» с процентом; Esc прерывает с подтверждением (3700–3718).
- **Найденное**:
  - курсор встаёт на начало совпадения (на конец при `SearchCursorAtEnd`, `MEditConfigCursorAtEnd` «Курсор в ко&нце», умолчание — нет);
  - совпадение выделяется потоковым блоком при `SearchSelFound` (`MEditConfigSelFound` «&Выделять найденное», умолчание — **нет**; без него найденное никак не подсвечивается);
  - без постоянных блоков прежнее выделение снимается (3775–3787);
  - экран **всегда** перестраивается: строка с совпадением ставится на `(ScrY−2)/4` строк от верха, если это значение меньше `(ScrY−5)/2−2`, иначе наверх — даже если совпадение уже было видно;
  - `LeftPos` подбирается так, чтобы правее совпадения было видно 8 столбцов (3789–3811).
- **Замена**:
  - на каждое совпадение (пока не выбрано «Все») временно подсвечивается найденное цветом выделения и задаётся вопрос «Замена»: `MEditAskReplace` «Заменить» / найденное в кавычках / `MEditAskReplaceWith` «на» / замена в кавычках, кнопки `MEditReplace` «&Заменить», `MEditReplaceAll` «&Все», `MEditSkip` «&Пропустить», `MEditCancel` «&Отменить» (3824–3862);
  - «Все» превращает весь остаток прохода в **один шаг отмены** (3864–3865);
  - в регулярных выражениях замена может ссылаться на группы; при «Сохранять стиль» строка замены подстраивается под регистр и разделители найденного (справка `@PreserveStyle`; реализация — `SearchAndReplaceString`, не изучалась);
  - замена, содержащая `\t` или `\r`, вводится как нажатия клавиш (Tab с учётом `ExpandTabs`, `\r` — Enter, то есть новая строка); иначе строка собирается напрямую (3874–3969).
- **«Всё» (Find All)** (4014–4118, `find_all_list` 3520–3645):
  - Меню снизу экрана (верх `ScrY−20`, до 10 пунктов) с заголовком `MEditSearchStatistics` «Вхождений: {0}, строк: {1}», колонками «номер строки │ позиция» и подсветкой совпадения в тексте строки; тема `FindAllMenu`.
  - Enter — перейти и закрыть; Ctrl+Enter и Ctrl+щелчок — перейти, не закрывая; Ctrl+↑/↓ — прокрутка редактора; Gray+ — сеансовая закладка; Ctrl+0…9 — закладки; F5 — меню во весь экран.
  - F4 / Alt+F4 — все / прошедшие фильтр строки в **новый редактор**. Это `EPHEMERAL`-окно (F2 работает как «Сохранить как», в историю не пишется) с именем `MEditSearchAllFileNameFormat` «{имя}{расширение}.Filtered.txt» или, если имя подходит под `Editor.SearchAllUseAltFileNameFormat` (умолчание `*.txt,*.log,*.md,*.csv,*.ini,*.cmd,*.map`), `MEditSearchAllFileNameFormatAlt` «{имя}.Filtered{расширение}» (4149–4217).

## 6. Переход (Alt+F8)

Диалог `GoToRowCol` общий с просмотрщиком (`stddlg.cpp:1081–1109`): заголовок `MGoTo` «Перейти / Go to», поле шириной 28 (история `LineNumber`, общая с просмотрщиком), разделитель, `[ ] MGoToHex` «16-ричное &значение / &Hex value», OK/Отмена. Тема справки `EditorGotoPos`. Флажок Hex запоминается в окне (`m_GotoHex`), начально выключен.

Формат (`GetRowCol`, 997–1079) — как в просмотрщике: `[+|-]значение[%]`, второй элемент через один из `" .,;:"`; `0x`/`$`/`h` — шестнадцатеричное, `m` — десятичное. Смысл в редакторе (`GoToPosition`, `editor.cpp:4732–4767`):
- первое значение — **номер строки** с 1; второе — **номер символа** в строке с 1 (реальная позиция, табуляция считается одним символом);
- `%` — процент от числа строк / от длины текущей строки;
- `+N` / `-N` — относительно текущей строки / позиции курсора;
- пустой элемент не меняет соответствующую координату (`12` — только строка, `:5` — только столбец).

Тонкости (выведено из кода):
- номер больше числа строк ведёт на последнюю строку (`GoToLine`, 4665–4724);
- `0` и уход «выше первой строки» через `-N` из-за беззнакового переполнения тоже дают последнюю строку (4742–4748);
- если цель была вне экрана, она становится **верхней** строкой экрана (4712–4713);
- без постоянных блоков переход снимает выделение (1979–1980).

## 7. Отмена и повтор

Модель — линейный список записей `EditorUndoData {тип, текст строки, конец строки, номер строки, позиция}` с указателем `UndoPos` (`editor.cpp:4769–4824`). Типы: `edit` (прежний текст строки), `insert_string`, `delete_string`, а также `begin` и `end` для группы (86–93).
- Записывается **вся строка до правки**, а не разница. Новая правка обрезает «будущее» после `UndoPos`: после отмены и новой правки повтор невозможен (4834–4844).
- **Склейка в один шаг.** Новая запись `edit` не создаётся, если предыдущая тоже `edit` той же строки, не взведён `FEDITOR_NEWUNDO`, и либо идёт группа, либо позиция отличается от прошлой не больше чем на 1 (4891–4899). Поэтому непрерывный набор или удаление в строке — один шаг.
- `NEWUNDO` (начать новый шаг) ставят ←, ↑/↓, PgUp/PgDn, Ctrl+↑/↓, Ctrl+Home/End/PgUp/PgDn, Ctrl+N/E, Home, Enter, вставка, сама отмена и сохранение (1513, 1687, 1746, 1763, 1787, 1842, 2490, 4250, 1966; `fileedit.cpp:1957`). → и End его не ставят, но склейку и так рвёт разрыв позиций.
- **Группы** `begin…end` — один шаг: Enter посреди строки, склейка строк Del/BS, удаление блока, вставка, сдвиг блока Alt+U/I, вертикальные операции, Xlat, замена с Tab/Enter, «Заменить все». Пустая группа удаляется (4867–4888).
- Отмена ставит курсор на строку и позицию правки, снимает выделение (`Undo`, 4941–5071). Повтор (Ctrl+Shift+Z) идёт по тем же записям вперёд (записи меняются местами с текущим состоянием).
- **Лимит** `Editor.UndoDataSize` = 100 МБ текста (`config.cpp:2018`, только far:config). Счётчик объёма **статический, общий для всех окон редактора** (`UndoDataSize`, 4783–4824). При превышении из начала списка текущего окна выбрасываются записи целыми группами (4914–4938). Ограничения по числу шагов нет.
- **После сохранения** история сохраняется. Запоминается `UndoSavePos`; если отменой или повтором вернуться ровно в эту точку, флаг «изменён» снимается (5067–5068, `fileedit.cpp:1915–1916`). Если точка сохранения выпала из истории (обрезка или лимит), флаг больше не снимается (`FEDITOR_UNDOSAVEPOSLOST`, 4836–4843, 4926–4927).
- При удалении строки сеансовые закладки на ней уходят в запись отмены и возвращаются при отмене (2955–2973, 5027). Обычные закладки 0…9 только сдвигаются по номерам (2948–2953, 3012–3016).

## 8. Строка статуса и заголовок консоли

Верхняя строка (`FileEditor::ShowStatus`, `fileedit.cpp:2254–2324`), цвет `COL_EDITORSTATUS` (чёрный на бирюзовом). Видна при `Editor.ShowTitleBar` (умолчание — да) и высоте окна больше 1; Ctrl+Shift+B переключает её во всех редакторах.

```
C:\work\notes.txt                     │* │UTF-8│Стр  12/340│Кол 9  │С 5  │R│1072
```

Хвост — `"│{изм}{режим}│{cp:5.5}│{Стр:.3} {строка/всего:>w}│{Кол:.3} {столбец:<3}│{С:.3} {символ:<3}{│атрибуты}│{код}"` (2299–2311):
- `изм` — `*`, если файл изменён, иначе пробел;
- `режим` — `-` при блокировке (Ctrl+L), `"` во время Ctrl+Q, иначе пробел;
- кодовая страница — `ShortReadableCodepageName`: `UTF-8`, `U16LE`, `U16BE`, `ANSI`, `OEM` или номер, ширина ровно 5;
- `MEditStatusLine` «Стр / Ln» (не больше 3 символов), «строка/всего»; ширина поля — длина «всего/всего», выравнивание вправо;
- `MEditStatusCol` «Кол / Col» — **экранный** столбец курсора с 1 (`GetTabCurPos()+1`), ширина 3, влево;
- `MEditStatusChar` «С / Ch» — **индекс символа** с 1 (`GetCurPos()+1`); с табуляцией «Кол» и «С» расходятся;
- атрибуты файла — только буквы `R`, `H`, `S` (если есть, со своим `│`) (`EditorGetFileAttributes`, 2330–2353; буквы — `fileattr.cpp:207–210`);
- код символа под курсором (суррогатная пара — одной кодовой точкой) по `Editor.CharCodeBase` (только far:config, умолчание 1): 0 — восьмеричный `0{:o}` (поле на 7), 1 — десятичный (на 5), 2 — шестнадцатеричный `{:X}h` (на 5). Для не-UTF страниц добавляется `/` и код байта в этой странице, если он отличается от Юникода, например `1072/224` для «а» в 1251 (`char_code`, `ansi_char_code`, 2189–2251). За концом строки поле пустое.

Имя слева — заголовок от плагина (`ECTL_SETTITLE`), заданный при открытии заголовок или полный путь, сокращённый `truncate_path` до оставшейся ширины (2173–2187, 2319). При `Clock` и полноэкранном окне справа резервируется место под часы и `│`; часы рисуются цветом `COL_EDITORCLOCK` (`interf.cpp:669`). Режим вставки/замены, тип блока и формат концов строк в статусе **не показываются**.

**Заголовок консоли**: `Interface.EditorTitleFormat` = `"%Lng %File"`; `%Lng` → `MInEditor` «редактирование / edit», `%File` → имя без пути (`ShowConsoleTitle`, 2068–2075; `config.cpp:2043`).

## 11. Геометрия и строка клавиш

Окно `{0,0,ScrX,ScrY}` (`fileedit.cpp:746, 888–904`):
- строка 0 — статус (при `ShowTitleBar` и высоте больше 1);
- строки 1..ScrY−1 — текст;
- строка ScrY — строка клавиш (при `ShowKeyBar` и высоте больше 2) (2798–2806).

Без статуса или строки клавиш текст занимает их место.

Внутри текстовой области (`ShowEditor`, `editor.cpp:238–397`):
- **Номера строк** (Ctrl+F3 или настройка) — слева колонка шириной `max(3, цифр в числе строк) + 1`: номер выровнен вправо, затем пробел, цвет `COL_EDITORLINENUMBERS`; ниже конца файла колонка закрашивается тем же цветом (336–358, 7283–7288). Переключение Ctrl+F3 действует только на это окно и не сохраняется.
- **Полоса прокрутки** — правый столбец, только если `ShowScrollBar` и строк больше высоты окна (`ScrollBarRequired`, `interf.cpp:1566–1569`; `editor.cpp:7207–7214, 7290–7293`). Вид тот же, что в просмотрщике (`▲ ░ █ ▼`); бегунок — номер верхней строки из числа строк.
- **Пустое место после конца файла.** При `AllowEmptySpaceAfterEof = false` верх экрана подтягивается так, чтобы под последней строкой не оставалось пустых строк (если файл длиннее окна) (255–264, 3245–3249).
- Если курсор оказался ниже экрана, экран сдвигается к курсору, а не курсор к экрану (272–275).

**Строка клавиш**: `KeyBar::SetLabels(lng::MEditF1)` — 96 идентификаторов подряд, группы Main, Shift, Alt, Ctrl, AltShift, CtrlShift, CtrlAlt, CtrlAltShift (как у просмотрщика, `keybar.cpp:196–206`). Непустые подписи:

## 12. История и кэш позиций

**История** (Alt+F11) общая с просмотрщиком, см. [12-far-viewer-reference.md](12-far-viewer-reference.md) §10. Записи редактора: `MHistoryEdit` «Редактор» + `:` + пробел или `-` для открытых с блокировкой (`HR_EDITOR_RO`, `history.cpp:264–282`). Обычная и «только чтение» считаются одной записью (`history.cpp:775`). Открытие такой записи восстанавливает блокировку (`FFILEEDIT_LOCKED`). Не пишутся окна с `DISABLEHISTORY` (файлы плагинов) и `EPHEMERAL`.

**Кэш позиций** (`poscache.hpp:75–96`, `poscache.cpp:66–127`, база `HistoryCfg`; старые записи чистятся по тем же 1000 записей / 90 дней, что и история просмотра, `poscache.cpp:60–64`):
- Ключ — полный путь, для файлов плагина — `PluginData + имя` (`GetCacheName`, `fileedit.cpp:2686–2692`).
- Хранится: строка курсора `Line`, строка курсора на экране `ScreenLine`, **экранный** столбец курсора `LinePos`, `LeftPos`, `CodePage` и 10 закладок `{Line, LinePos (реальный), ScreenLine, LeftPos}` (`POS_NONE = -1` — пусто) (`GetCacheParams`, `editor.cpp:6998–7006`).
- Пишется при закрытии (`OnDestroy`, `fileedit.cpp:2097–2098`) и перед Shift+F4 (1161–1162); не пишется при `DISABLESAVEPOS` («Перегрузить») и неудачном открытии.
- Кодовая страница пишется **всегда** (кроме `BadConversion`). Справка говорит «если страница была выбрана вручную», но в коде такой проверки нет (2714). Применяется она при любом открытии с `CP_DEFAULT`, если включено `SaveEditorPos` (без него прочитанная запись обнуляется вместе со страницей).
- `SaveEditorPos = false` при включённых закладках — в базу пишется нулевая позиция, а прочитанная позиция обнуляется (`poscache.cpp:78–82, 108–111`). Закладки читаются и пишутся только при `SaveEditorShortPos`.
- **Восстановление** (`SetCacheParams`, `editor.cpp:6909–6996`):
  - явная строка из `far -e10:5` важнее кэша: строка ставится на середину экрана (`ScreenLine = min(высота/2, строка)`), позиция — реальная;
  - иначе при `SavePos` верх экрана = `Line − ScreenLine`, курсор опускается на `ScreenLine` строк, затем ставятся экранный столбец и `LeftPos`.
- **Из просмотрщика** (`StartLine = −2`): байтовое смещение переводится в строку суммированием длин строк в байтах — UTF-8 через `get_bytes_count`, UTF-16 делением смещения на 2, BOM вычитается. Для DBCS считаются символы, а не байты, так что позиция будет неточной. Найденная строка становится верхней. Если она совпадает с верхом экрана из кэша, курсор и столбец берутся из кэша (6914–6963).
- **Обратно в просмотрщик** (F6) передаётся байтовое смещение начала верхней строки экрана (`GetCurPos`, 5101–5138).

## 13. Прочее

**События и API плагинов** (для afar не нужны, перечислены, чтобы знать, что пропускать):
- события `EE_READ` после открытия (через `CallbackWindow`, `fileedit.cpp:840–848`), `EE_SAVE`, `EE_REDRAW` при каждой отрисовке, `EE_CLOSE`, `EE_GOTFOCUS`/`EE_KILLFOCUS`, `EE_CHANGE` по подписке (`editor.cpp:7216–7226`);
- `ProcessEditorInput` получает каждую клавишу и событие мыши **до** редактора (`fileedit.cpp:1089–1097, 2124–2127`);
- `EditorControl` (`ECTL_*`, `editor.cpp:5564`; `fileedit.cpp:2419–2679`) — позиция, вставка, выделение, раскраска, настройки окна, сохранение, закладки, строка клавиш, заголовок;
- макросостояние `MCODE_V_EDITORSTATE` (биты: новый, F6, удалить при закрытии, изменён, потоковый/вертикальный блок, сохранялся, замена, блокировка, постоянные блоки, модальность; `fileedit.cpp:918–935`) и функции `Editor.Sel/SetStr/InsStr/DelLine/SelValue`, `BM.*` (`editor.cpp:511–799`).

**Временные файлы.** Окно с «удалить при закрытии» (файл плагина, `DELETEONCLOSE` / `DELETEONLYFILEONCLOSE`) удаляет файл (и пустую папку) в деструкторе, только если тот же файл не открыт в другом окне и не было сохранения (`fileedit.cpp:482–513, 1856`). При переходе F6 флаг передаётся просмотрщику (1046–1053).

**Ограничения и производительность.**
- Весь файл в памяти: узел списка на строку, `Edit` с `std::wstring`, курсором, выделением и флагами. Память — примерно `2 × символов` плюс постоянные накладные расходы на строку. Предупредить о больших файлах может только `FileSizeLimit`.
- `GoToLine` идёт по списку от ближайшего из «текущая / начало / конец» (`editor.cpp:4665–4708`); `GetStringByNumber` — аналогично. Номера строк хранятся в итераторах, поэтому номер текущей строки известен без подсчёта.
- Поиск построчный, линейный, с прогрессом и Esc. Загрузка — поток с буфером 64 КБ (`filestr.cpp:64`).
- Позиции в строке — `int`; длинные строки не режутся.
- Отмена хранит полные копии изменённых строк; правка в очень длинной строке дорога по памяти (лимит 100 МБ общий).

**Заметки для afar.**
- Модель редактора — **строки и номер строки**, в отличие от байтового смещения просмотрщика. При F6 в обе стороны позиция пересчитывается: только верх экрана, с потерей точности для DBCS.
- Концы строк хранятся построчно, и `\r\r\n` — законный тип. Для совместимости с Far буфер afar должен хранить конец у каждой строки и не нормализовать его без «Сохранить как».
- Far **не следит** за файлом во время редактирования. Единственная проверка — сравнение времени и размера при сохранении с выбором «Да / Сохранить как… / Отмена»; перечитать можно только повторным открытием с «Перегрузить». План afar «спросить: перечитать или оставить своё» ([11-viewer-editor.md](11-viewer-editor.md), «Буфер — единственная правда») — это уже расширение Far, а не повторение.
- Far закрывает файл после чтения и пишет через временный файл + `ReplaceFileW` (с исключениями для потоков, ссылок и жёстких ссылок). Это стоит повторить: безопасное сохранение и не держать файл открытым — важно, когда тот же файл меняет Bash агента.
- F8/Shift+F8 в открытом файле **переинтерпретируют байты**, а не перекодируют текст; перекодирует только «Сохранить как». Это легко перепутать.
- Отмена — линейная, на уровне строк, со склейкой по соседству позиций; «Заменить все» и вставка — один шаг. Правка агента одним шагом отмены ([11-viewer-editor.md](11-viewer-editor.md), «Три слоя») ложится на эту модель как группа `begin…end`.
- Поиск в редакторе не заворачивает через край файла и всегда перестраивает экран — в отличие от просмотрщика. Найденное подсвечивается только при «Выделять найденное» (выключено по умолчанию).
- Свободные в Far клавиши, которые afar может занять: `Ctrl+Enter` (в редакторе Far ничего не делает — проверено по коду: в `ProcessKeyInternal` её нет, а `Edit::ProcessKey` игнорирует Enter-клавиши, `edit.cpp:1401`), F3, F5, F9, Alt+F1…F6. `Ctrl+Shift+Enter` и `Shift+Enter` заняты вставкой имён файлов, Alt+стрелки — вертикальным блоком.
