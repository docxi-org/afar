# 13. Сессии агента и меню панели агента

Как пользователь управляет агентом из afar: меню панели агента, сессии Claude Code (выбор прошлой сессии каталога, имена), а дальше — несколько сессий одновременно, рядом и связанные между собой. Меню и одна сессия делаются сейчас; несколько сессий — после основной работы агента (этап 2 просмотрщика, редактор), но то, что дорого переделывать, закладывается сразу.

## Меню панели агента

**Вызов:** `F9`, когда фокус на агенте (Claude Code эту клавишу не использует), и щелчок по верхней рамке панели агента — меню открывается сразу на разделе под мышью, как щелчок по верхней строке в Far. Там, где верхняя рамка — граница с панелями (агент внизу), щелчок (нажать и отпустить на месте) открывает меню, а перетаскивание двигает границу.

Это строка меню в стиле Far (как `F9` у панелей), четыре раздела в таком порядке:

| Раздел | Пункты |
|---|---|
| **Сессия** | новая сессия в каталоге активной панели; продолжить сессию этого каталога… (список); перенести сессию в каталог активной панели (`/cd`); перезапустить агента (та же сессия); переименовать… (`/rename`); сжать контекст… (`/compact` с указаниями); очистить (`/clear`); прервать ход (`Esc`) |
| **Режим** | режим разрешений: обычный, принимать правки, план, авто, не спрашивать, обходить; модель: Opus, Sonnet, Haiku, другая…; усилие (`/effort`); наблюдение afar: по запросу / live |
| **Связь** | afar как IDE агента (флажок); события afar будят агента — Channels (флажок); протокол IDE — `ide.log` в просмотрщике; журнал сессии в просмотрщике; «Агент и разрешения…» |
| **Вид** | панель агента вверху / внизу; выше (`Ctrl+↑`); ниже (`Ctrl+↓`); погасить / показать |

Как afar выполняет пункты:
- **Команды Claude Code** (`/rename`, `/compact`, `/clear`, `/model`, `/effort`, `/cd`) — afar набирает их в поле ввода агента и нажимает Enter. `/rename`, `/model`, `/effort` у Claude Code «немедленные»: выполняются и во время хода агента. Остальные встают в очередь до конца хода. Если в поле ввода уже есть недописанный текст, команда допишется к нему — поэтому пункты меню предупреждают об этом в строке статуса (очистить поле ввода надёжно нельзя).
- **Режим разрешений** у Claude Code переключается только по кругу (`Shift+Tab`), без возможности выбрать конкретный — поэтому afar перезапускает агента с `--resume <сессия> --permission-mode <режим>`. Разговор продолжается, текущий ход прерывается.
- **Новая / продолжить / перезапустить** — afar завершает текущий `claude` (как при выходе, с ожиданием) и запускает новый в нужном каталоге: без `--resume` (новая), с `--resume <id>` (выбранная или та же).
- **Связь и Вид** — настройки afar (`config.toml`) и команды раскладки.

**Подтверждения** (`[confirm] agent`, флажок «Действия с сессией агента» в «Параметры → Подтверждения»):
- `/compact` — диалог «Сжать контекст…» с полем для указаний, что сохранить (необязательно; `/compact <указания>`); он же и подтверждение, поэтому показывается всегда;
- `/clear` — новая сессия с пустым контекстом;
- новая сессия, продолжить другую сессию, перезапустить, смена режима разрешений — если агент работает: его ход прервётся (разговор сохранится);
- режим «обходить разрешения» — всегда, с предупреждением, что агент будет выполнять всё без вопросов.

Без подтверждения: перенос в каталог (`/cd`), имя, модель, усилие, наблюдение, «Связь», «Вид», «Прервать ход» — обратимые или и так явные действия.

## Сессии каталога

Claude Code хранит разговоры в `~/.claude/projects/<каталог>/<id>.jsonl`, где `<каталог>` — путь, в котором каждый символ, кроме латинских букв и цифр, заменён на `-` (`F:\AGI\far` → `F--AGI-far`). Сессия продолжается (`--resume <id>`) только из своего каталога.

**Запуск afar** (`[agent] on_start`, решено 2026-10-09): `"last"` (по умолчанию) — агент продолжает последний разговор, который afar вёл в каталоге запуска (`state.json` хранит последнюю сессию каждого каталога, до 50); если afar в этом каталоге ещё не работал или разговор пуст — новый. Последний разговор каталога вообще (как `claude --continue`) afar не берёт: там бывают чужие сессии, идущие сейчас в другом `claude`. `"new"` — всегда новый разговор. Перезапуск в режиме разработки продолжает разговор всегда.

**«Продолжить сессию этого каталога…»** — меню со списком сессий каталога активной панели, новые сверху: имя, дата и время последнего изменения, размер. Выбор перезапускает агента в этом каталоге с `--resume <id>`. Сессия, которая сейчас открыта, отмечена.

**Имя сессии** в списке:
1. `customTitle` последней строки `{"type":"custom-title"}` — имя, заданное `/rename` (или `--name`);
2. иначе `aiTitle` последней строки `{"type":"ai-title"}` — имя, которое Claude Code дал сам;
3. иначе `lastPrompt` из `{"type":"last-prompt"}` — последний запрос пользователя;
4. иначе id.

Файлы разговоров бывают десятки мегабайт, поэтому afar читает начало (256 КБ) и конец (1 МБ) файла; имя, заданное в середине длинного разговора и не повторённое позже, может не попасть — тогда видно имя от Claude Code.

**Имена.** «Переименовать…» спрашивает имя и отправляет `/rename <имя>`. afar показывает имя сессии в заголовке рамки панели агента («Агент · <имя> · работает»); при продолжении сессии берёт его из файла разговора. Имена нужны и для нескольких сессий: по ним сессии различают в списке, во вкладках и в сообщениях друг другу.

**Перенос в каталог** (`/cd <путь>`) — Claude Code переносит текущую сессию в другой рабочий каталог (дальше она хранится уже там). Это пункт «перенести сессию в каталог активной панели», когда пользователь ушёл панелью в другой проект и хочет, чтобы агент пошёл за ним.

**`/clear`** начинает новую сессию с новым id (старая остаётся на диске). afar после `/clear` узнаёт новый id из хука `SessionStart` (во входе хука есть `session_id`) — иначе перезапуск в режиме разработки продолжил бы старую сессию.

## Несколько сессий (после основной работы агента)

### Модель

- **Сессия** — не только процесс `claude`: у каждой свой id Claude Code и имя, свой каталог, своя позиция в журнале afar («что агент уже видел»), свой режим наблюдения, свой токен MCP и хуков, свой сервер протокола IDE, своя очередь событий Channels.
- **Журнал общий:** действия пользователя видят все сессии; записи агентов помечены, какой сессией сделаны.
- **Активна та сессия, что на экране.** Только ей уходят выделение в просмотрщике (`selection_changed`), `Ctrl+Enter`, «показать файл агенту». Сессии вне экрана продолжают работать; afar показывает их состояние (работает, ждёт ответа на вопрос, закончила) — в списке сессий и значком на вкладке.

### Раскладка

- **Вкладки** в закреплённом окне агента: одна сессия на экране, переключение — меню «Сессия» и клавиши.
- **Две сессии рядом**, как панели Far: место агента делится на два окна (разбиение в оконном менеджере), `Tab` между ними, как между панелями; активна та, где фокус.
- **Агент панели** — вариант «рядом»: левая сессия работает в каталоге левой панели, правая — в каталоге правой. Естественно для Far: две панели, два проекта, два агента.

### Связанные сессии

- Пользователь **связывает** сессии (меню «Сессия → Связать с…»). afar сообщает каждой: «пользователь связал тебя с сессией "<имя>" (каталог, чем она занята); раз связал — значит, вы делаете общее дело», — через событие Channels, а без них — добавкой к следующему запросу.
- Инструменты afar для связанных сессий:
  - `afar_sessions` — кто ещё есть: имя, каталог, состояние, последний ответ;
  - `afar_send(session, text)` — сообщение другой сессии.
- Доставка — **Channels**: сообщение будит получателя без участия человека. Поэтому вопрос с подтверждением Channels при каждом запуске агента (docs/11, «Эксперимент») надо решить до нескольких сессий. Запасной путь — вставить текст в поле ввода получателя (пользователь сам нажимает Enter).
- **Чего нет у Claude Code и есть у afar:** afar видит правки всех сессий (хуки `PostToolUse`) и предупреждает, когда две сессии правят один файл; передаёт сессии контекст другой (её последний ответ, изменённые ею файлы).

### Риски

- Расход токенов растёт с числом работающих сессий — по умолчанию одна сессия, остальные создаются явно.
- Место на экране: две сессии рядом уже узкие — вкладки по умолчанию, «рядом» по выбору.
- Сессии правят одни файлы — предупреждения afar, а в редакторе afar — правки через буфер (docs/11, «Редактор и агент»).

## Открытые вопросы

1. Клавиши переключения сессий (вкладки) и фокуса между двумя сессиями рядом.
2. Сколько сессий держать живыми одновременно и что делать со «спящими» (завершать процесс и продолжать по `--resume` при переключении?).
3. Связывание: только парами или группами; может ли агент сам предложить связать сессии.
4. Channels без подтверждения при запуске (одобренный канал) — условие для `afar_send` без участия человека.
