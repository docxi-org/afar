# Просмотр и редактирование

Встроенный просмотрщик (`F3`) и редактор (`F4`): что умеет Far, что afar делает так же, что лучше, и как в работу с файлом включается агент. Подробный разбор просмотрщика Far по исходникам (клавиши, геометрия, строки интерфейса, умолчания) — в [12-far-viewer-reference.md](12-far-viewer-reference.md).

Возможности самого редактора (как в Far и лучше) будут описаны отдельно; совместная работа с агентом в редакторе — в разделе [«Редактор и агент»](#редактор-и-агент). Каналы связи с Claude Code, общие для просмотра и редактора, — в разделе [«Связь с Claude Code»](#связь-с-claude-code).

## Место в интерфейсе

- Просмотрщик и редактор — **экраны** оконного менеджера ([08-windows.md](08-windows.md)). Они занимают место панелей, а панель агента остаётся внизу. Позже — список экранов `F12`, переключение `Ctrl+Tab`, несколько открытых файлов одновременно.
- Агент видит, какой файл открыт и что выделено, и может сам открывать файлы на нужном месте и подсвечивать фрагменты (см. [«Агент и просмотр»](#агент-и-просмотр)).

## Просмотр в Far

### Что открывает

Встроенный просмотрщик Far показывает **текст и байты**. Картинки, PDF, документы Office и архивы он не открывает — это делают плагины.

| Что | Как в Far |
|---|---|
| Однобайтовые кодировки (OEM, ANSI и другие кодовые страницы Windows), азиатские двухбайтовые, UTF-8, UTF-16 LE/BE | поддерживаются; UTF-7 и 4-байтовые (GB18030) — нет |
| Определение кодировки | сохранённая для файла → BOM → анализ первых 32 КБ (проверка UTF-8, эвристики UTF-16, статистические детекторы) → ANSI |
| Двоичные файлы | если в первых 2 КБ есть нулевой байт — сразу режим дампа |
| Файлы любого размера | файл не читается целиком: позиция на экране — **байтовое смещение**, строки вокруг него находятся сканированием; открывается мгновенно |
| Растущие файлы | раз в секунду проверяется размер; если экран стоит на конце, просмотр едет за ним (как `tail -f`) |
| Неверные последовательности байтов | заменяются на `�` |
| Папки | `F3` на папке считает её размер, а не открывает просмотр |

### Режимы и отображение

- **Текст.**
  - Конец строки — CR, LF, CRLF.
  - Табуляция раскрывается до кратного 8.
  - Управляющие символы показываются глифами (`☺☻♥…`), `\0` — по настройке.
  - Строка длиннее 10000 символов режется.
  - Без переноса строки прокручиваются вбок, на краях — стрелки `«` `»`.
- **Перенос.**
  - `F2` — по ширине окна.
  - `Shift+F2` — по словам.
- **Hex.**
  - Строка `0000000000: 54 68 65 … │ … The quick…`, по 16 байт (79 столбцов).
  - `Alt+←/→` меняют число байт в строке.
- **Дамп.** Символы сплошным потоком, без деления на строки.
- **Строка статуса.** Имя, режим (`t`/`h`/`d`), кодировка, размер, столбец, процент, часы.
- **Строка клавиш.** Подписи меняются по режиму: F2 «Сверн/Развер», F8 — имя *следующей* кодировки.
- **Полоса прокрутки** включается по `Ctrl+S`.

### Возможности

- **Поиск `F7`.**
  - Текст или hex-байты; регистр, целые слова, регулярные выражения.
  - Найденное становится выделением.
  - `Shift+F7` / `Пробел` — дальше, `Alt+F7` — назад; на краю файла вопрос «Продолжить с начала?».
- **Переход `Alt+F8`.**
  - Смещение (десятичное, `0x…`, `…h`) или процент, абсолютно или относительно (`+`/`-`), плюс столбец.
  - **Перехода к номеру строки нет**, номеров строк тоже нет.
- **Кодировки.** `F8` переключает ANSI ↔ OEM, `Shift+F8` открывает меню кодировок с повторным автоопределением.
- **Закладки и откат.** Десять закладок: левый `Ctrl+0…9` — перейти, правый `Ctrl` или `Ctrl+Shift+0…9` — поставить. `Ctrl+Z` / `Alt+BS` откатывают перемещения.
- **Соседние файлы.** `Gray+` / `Gray-` открывают следующий или предыдущий файл панели.
- **Связь с остальным Far.**
  - `F6` — в редактор на той же позиции.
  - `Ctrl+F10` — курсор панели на этот файл.
  - `Ctrl+O` — экран пользователя.
- **Выделение и копирование.** `Shift`+щелчок задаёт начало и конец, `Ctrl+C` копирует.
- **Память о файлах.** Позиция, кодировка, режим, перенос и закладки запоминаются для каждого файла. История просмотра — `Alt+F11`.
- **Быстрый просмотр `Ctrl+Q`.** Просмотр в соседней панели; для папки — сводка размеров.

## Просмотр в afar

### Как в Far

Всё перечисленное выше повторяется с той же моделью: позиция — байтовое смещение, строки находятся сканированием, файл любого размера открывается сразу. Геометрия, клавиши, тексты и цвета — по [12-far-viewer-reference.md](12-far-viewer-reference.md).

### Лучше, чем в Far

1. **Номера строк и переход к строке.**
   - Индекс начал строк строится в фоне, поэтому мгновенное открытие больших файлов не теряется.
   - Пока индекс не готов, номер показывается как «≈» или не показывается.
   - `Alt+F8` понимает и номер строки.
2. **Подсветка синтаксиса** по расширению или содержимому (код, конфиги, разметка); включается отдельно.
3. **Структурные режимы:**
   - **JSON** — с отступами и сворачиванием узлов;
   - **CSV/TSV** — таблицей с выровненными столбцами и закреплённой строкой заголовков;
   - **логи** — уровни (`ERROR`, `WARN`, …) цветом, отметки времени приглушённо.
4. **Поиск:**
   - подсветка **всех** совпадений на экране, не только текущего;
   - счётчик «3 из 17» в строке статуса;
   - список всех найденных строк (как результаты grep), по которому можно переходить.
5. **Слежение за файлом.** Явный режим «следить» (`End` на конце файла) с индикатором в строке статуса. Плюс **живой фильтр строк** — показывать только строки, подходящие под шаблон (аналог `tail -f | grep`).
6. **Документы и архивы (позже).**
   - PDF, DOCX и подобные — как извлечённый текст.
   - Архив — как список содержимого.
   - Картинки — в терминалах с поддержкой графики (sixel), иначе сведения о файле.

## Агент и просмотр

Здесь afar сильнее всего отличается от Far: просмотр — общее поле пользователя и агента.

### Агент открывает и показывает

- **`afar_view`** открывает файл в просмотрщике и ставит его на нужное место. Параметры:
  - `path`;
  - одно из: `line` (с `column`), `offset`, `pattern` (первое совпадение, регулярное выражение);
  - `mode` (`text` / `hex`), `encoding`;
  - `highlight` — подсветить строку или диапазон сразу.

  Пример: «вот здесь ошибка в конфиге» — файл открыт, строка видна и подсвечена.
- **`afar_highlight`** подсвечивает строки или диапазоны в открытом (или открываемом) файле. У каждой пометки есть:
  - **подпись** — показывается на полях и в строке статуса, когда курсор на пометке;
  - **вид** — `info` / `warning` / `error`, разные цвета;
  - **`flash`** — коротко мигнуть фрагментом, чтобы привлечь взгляд («вот здесь»);
  - **`ttl_s`** — снять пометку через заданное время (по умолчанию пометка держится, пока файл открыт).

  Клавишами пользователь переходит от пометки к пометке (как по закладкам). `Esc` или повторный вызов снимает пометки.
- Пометки агента видны и в списке экранов, и в истории: «агент отметил 3 места в `config.toml`».

### Привязка пометок

Пометка задаётся строками, но привязывается к **месту в тексте**: если файл перечитан (агент поправил его, лог вырос, пользователь сохранил правку в редакторе), позиции пересчитываются по diff старого и нового текста. Пометка на удалённых строках снимается или показывается как устаревшая (приглушённо, с подписью «место изменилось»).

### Этикет внимания

Агент показывает, но не перехватывает:
- если пользователь сейчас в другом файле или печатает в редакторе, `afar_view` открывает **новый экран** и показывает уведомление («агент открыл `config.toml:42`»), а текущий экран не трогает;
- автоматически переводить пользователя к месту, куда указывает агент, — только в режиме **«следовать за агентом»** (включается явно, индикатор в строке статуса), как follow в совместном редактировании;
- у агента свой указатель (курсор-метка), курсор и прокрутка пользователя без его ведома не меняются;
- мигание короткое, пометки снимаются по `Esc`.

### Агент видит, что смотрит пользователь

- **Журнал.** События `FileOpened { path, mode }` и `ViewerSelection { path, lines, text_sample }`; выделение — с задержкой, одной записью на серию.
- **MCP `afar_viewer_state`.** Открытый файл, видимые строки, выделение (диапазон и текст, с ограничением размера), текущий поиск. Это позволяет выделить кусок и спросить «что это значит?»: агенту не нужно гадать, о чём речь.
- **Режим live.** Вместе с запросом агенту уходит «пользователь смотрит `file.rs`, строки 120–160, выделено 131–135».
- **Выделение — штатно для Claude Code.** afar сообщает выделение уведомлением `selection_changed` протокола IDE ([«Связь с Claude Code»](#протокол-ide-claude-code)), и Claude Code сам прикрепляет его к следующему запросу пользователя («The user selected the lines X to Y from …») — в любом режиме наблюдения. Выделение передаётся **одним** путём: если оно идёт через `selection_changed`, в журнал для live-режима оно не дублируется (в журнале остаётся только факт `ViewerSelection` без текста).

### Пользователь обращается к агенту из просмотра

- Клавиша **«спросить агента о выделенном»** (`Ctrl+Enter` в просмотре — в просмотрщике Far она свободна, [12-far-viewer-reference.md](12-far-viewer-reference.md#4-клавиши-просмотрщика)):
  - вставляет в поле ввода агента ссылку `@file.rs#L131-135` — уведомлением `at_mentioned` протокола IDE, а не набором текста в PTY агента;
  - переводит фокус на панель агента;
  - пользователь дописывает вопрос.
- Та же клавиша в редакторе **передаёт ход агенту** ([«Передача хода»](#передача-хода)): одна клавиша «к агенту» везде.

### Правки агента в открытом файле

Просмотрщик показывает **диск**: агент правит файл своими инструментами (`Edit`, `Write`), просмотр это отражает. (В редакторе наоборот — правда в буфере, агент на диск не пишет, см. [«Редактор и агент»](#редактор-и-агент).)

- Если агент меняет файл, который сейчас открыт, просмотр **перечитывается сам** (слежение за ФС уже есть, [04-agent.md](04-agent.md)).
- **Изменённые строки отмечаются на полях** (как diff): добавленные, изменённые, удалённые места. Пометки агента пересчитываются ([«Привязка пометок»](#привязка-пометок)).
- Переход к месту правки — только в режиме «следовать за агентом» ([«Этикет внимания»](#этикет-внимания)); иначе — уведомление.
- Пометки правок держатся, пока файл открыт, или до `Esc`.
- **Проверка правки до записи (по настройке).** Правка агента показывается в просмотрщике как diff на подтверждение, и только после «принять» `claude` пишет файл. Механизм — `openDiff` протокола IDE ([«Связь с Claude Code»](#протокол-ide-claude-code)). Работает, только когда Claude Code спрашивает разрешение на правку (не в режиме acceptEdits); вопрос в терминале агента появляется одновременно, побеждает первый ответ.

## Устройство

- **Модель.** Верх экрана — байтовое смещение (как в Far). Строки ищутся сканированием вперёд и назад от него. Отдельно в фоне строится индекс строк (для номеров и перехода к строке). Чтение — блоками с кэшем, файл целиком не загружается.
- **Индекс строк нужен агенту**, даже если номера строк на экране не показываются: `afar_view(line)`, `afar_highlight` и `afar_viewer_state` говорят строками. Пока индекс не достроен до нужного места, вызов агента ждёт его (большой файл) или досчитывает сканированием от ближайшей известной точки.
- **Кодировки.**
  - Декодирование — `encoding_rs`.
  - Определение: BOM → проверка UTF-8 → эвристики UTF-16 → `chardetng` → кодировка по умолчанию.
  - Кодовые страницы Windows — через `encoding_rs` и таблицы Windows, где их нет.
- **Слои подсветки.** Одна модель для просмотрщика и редактора: набор диапазонов с источником (`search`, `selection`, `agent`, `diff`, `syntax`) и стилем. Порядок наложения: синтаксис < правки < найденное < пометки агента < выделение.
- **Подсветка синтаксиса.** `syntect` (грамматики Sublime) или `tree-sitter`. Решение — при реализации; обе работают по видимой части, не по всему файлу.
- **Память о файлах.** Позиция, кодировка, режим, перенос и закладки — в истории просмотра (SQLite, вместе с историями M2).
- **Растущие файлы.** Слежение через `notify` вместо опроса раз в секунду; для сетевых дисков — опрос.
- **Команды.** Клавиши просмотра — команды с именами (`viewer.search`, `viewer.goto`, …) в своём контексте раскладки клавиш ([03-ui-and-keys.md](03-ui-and-keys.md)).

## Этапы

1. **Как в Far.**
   - Экраны просмотрщиков в оконном менеджере, список экранов `F12`, переключение `Ctrl+Tab` — агент открывает файлы в новом экране ([«Этикет внимания»](#этикет-внимания)).
   - Экран просмотрщика, текст / hex / дамп, кодировки и их определение, перенос.
   - Строки статуса и клавиш.
   - Поиск, переход, закладки, откат.
   - Память о файлах, слежение за ростом файла, `Gray+/-`, `F6` (когда будет редактор), `Ctrl+F10`.
2. **Агент** (сделано 2026-10-07; индекс строк — по запросу, с опорными точками, а не в фоне; клавиши пометок — `Alt+↓`/`Alt+↑`, `Esc` снимает; «следовать за агентом» — в меню агента). До него — эксперимент с Channels и протоколом IDE на живом `claude` ([«Связь с Claude Code»](#связь-с-claude-code)): от него зависят «спросить о выделенном» и проверка правки до записи.
   - Индекс строк в фоне (без показа номеров) — нужен инструментам агента.
   - `afar_view`, `afar_highlight` (с `flash`, `ttl_s`, привязкой к месту), `afar_viewer_state`.
   - События просмотра в журнале.
   - Протокол IDE: `selection_changed`, `at_mentioned` → «спросить агента о выделенном».
   - Пометки правок агента в открытом файле; режим «следовать за агентом».
   - По настройке — проверка правки агента до записи (`openDiff`).
3. **Улучшения просмотра.**
   - Номера строк на экране и переход к строке.
   - Подсветка всех совпадений, счётчик, список найденного.
   - Подсветка синтаксиса.
   - Режимы JSON / CSV / логов.
   - Режим «следить» и живой фильтр.
4. **Позже.** Документы как текст, архивы как список, картинки.

## Редактор

Как устроен редактор Far — по исходникам, с клавишами, диалогами, строкой статуса и умолчаниями — в [17-far-editor-reference.md](17-far-editor-reference.md). Здесь — что afar повторяет, что делает лучше и как устроен. Совместная работа с агентом — в следующем разделе.

### Как в Far

- **Модель текста Far** (§3 справочника): курсор за концом строки (по умолчанию включён), табуляция (размер 8, три режима преобразования), горизонтальная прокрутка, общая для экрана, без переноса строк; режим замены (`Ins`), блокировка правки (`Ctrl+L`); потоковые и вертикальные блоки, постоянные блоки (по умолчанию выключены), «Del удаляет блоки»; разделители слов Far.
- **Концы строк — у каждой строки свои**, как в Far: `LF`, `CR LF`, `CR`, `CR CR LF`; смешанные сохраняются как были, меняет их только «Сохранить как». Новая строка (`Enter`) получает конец текущей.
- **Клавиши и диалоги — как в Far** (§4–6): движение, выделение, буфер обмена, удаление, `F2` / `Shift+F2` / `Shift+F10` / `F4` / `F10` / `Esc`, `F6` ↔ просмотрщик на той же позиции, поиск и замена, «найти всё», переход `Alt+F8`, закладки, `F8` / `Shift+F8` (переинтерпретация байтов, а не перекодирование — как в Far), `Ctrl+F3` — номера строк.
- **Чтение и запись** (§2): определение кодировки — то же, что в просмотрщике (`viewer/codepage.rs`); BOM запоминается; файл не держится открытым; запись — через временный файл и `ReplaceFileW` (безопасное сохранение); `F2` пишет всегда; вопросы «изменён внешней программой» при сохранении, «только для чтения», «сохранить при выходе», «файл удалён».
- **Отмена** (§7): линейная, ввод подряд в одной строке — один шаг, `Enter`, склейка строк, операции с блоком, вставка, «Заменить все» — один шаг; возврат отменой к точке сохранения снимает «изменён».
- **Строка статуса и строка клавиш** (§8, §11) — формат Far; память позиции и кодировки, история `Alt+F11` (§12).

### Лучше, чем в Far

- **Слежение за файлом на диске.** Far проверяет файл только при сохранении. afar следит, пока файл открыт (как просмотрщик): буфер без правок перечитывается сам, с сообщением; с правками — вопрос «Перечитать / Оставить своё» (и при сохранении — вопрос Far). Нужно для работы с агентом: его Bash может поменять открытый файл.
- **Кодировка файла без своей кодировки.** Чистый ASCII и новый файл открываются в UTF-8, а не в ANSI, как в Far (решено 2026-10-07 по проверке агентом): иначе первое же русское слово уходит на диск в 1251, а инструменты агента и прочие программы читают файл как UTF-8 и портят его. Кодовая страница из настроек (`[viewer] default_codepage`) по-прежнему главнее.
- **Большие файлы.** Файл открывается целиком; перед файлом от 64 МБ (`[editor] large_file_mb`) — вопрос, открыть ли его в редакторе (по умолчанию — просмотрщик).
- Позже: подсветка синтаксиса и пометки (общие с просмотрщиком), показ пробелов клавишей, перенос по словам.

### Устройство

- **Буфер** — список строк, как в Far: у строки текст и свой конец строки (`Eol`: нет, `LF`, `CR LF`, `CR`, `CR CR LF`). Строк всегда не меньше одной; файл с завершающим переводом строки показывается с пустой последней строкой без конца (как в Far). Текст хранится в Юникоде, кодировка и BOM файла — у буфера; запись — обратно в кодировку файла, с проверкой, что всё кодируется.
- **Позиции**: строка и индекс символа; экранный столбец считается с учётом табуляции и широких символов (как `RealPosToVisual` в Far). Курсор может стоять за концом строки.
- **Версии.** У буфера счётчик версий, растущий на каждой правке; агенту отдаётся разница от версии, которую он видел (`similar`), — раздел «Редактор и агент».
- **Отмена** — журнал правок: правка — замена диапазона строк (что было → что стало) с положением курсора до и после; группы `begin…end` (как в Far) — один шаг; порция агента — тоже группа. Склейка ввода в одной строке — по правилам Far.
- **Окно** — экран оконного менеджера `ScreenId::Editor` (как у просмотрщика); клавиши — команды контекста `Ctx::Editor` в `COMMANDS` (имена `editor.*`), набор символов и неназначенное — самому редактору.
- **Слежение** — проверка времени и размера файла раз в секунду для экрана на виду и при переключении на него (как `Viewer::check_changed`).
- **Настройки** — `[editor]` в `config.toml` (размер и режим табуляции, курсор за концом строки, постоянные блоки, «Del удаляет блоки», автоотступ, номера строк, порог большого файла); позиции и кодировки — в памяти позиций (общей с просмотрщиком), история — `Kind::Edit` в `history.db`.

### Этапы

Порядок решён 2026-10-07: агент — сразу после базового редактора, остальное из Far — потом.

1. **Базовый редактор.**
   - Открытие: `F4` в панели, `Shift+F4` (диалог «Открыть/создать» с кодировкой, пустое имя — новый файл), `F6` из просмотрщика и обратно; файл уже открыт — переключиться в его экран; вопрос о большом файле.
   - Модель Far: концы строк по строкам, табуляция, курсор за концом строки, режим замены, `Ctrl+L`.
   - Клавиши: движение, потоковое выделение (`Shift`), `Ctrl+A` / `Ctrl+U`, буфер обмена (`Ctrl+C/X/V`, `Ctrl+Ins`, `Shift+Ins/Del`), `Ctrl+D`, удаление и правка (`Del`, `BS`, `Ctrl+BS`, `Ctrl+T`/`Ctrl+Del`, `Ctrl+K`, `Ctrl+Y`, `Enter`, `Tab`, `Ctrl+Q`), отмена и повтор, `Ctrl+F` — имя файла, `Ctrl+F3`, `Ctrl+B`, `Ctrl+O`.
   - Сохранение и выход: `F2`, `Shift+F2` (имя, кодировка, BOM, концы строк), `Shift+F10`, `F4` / `F10` / `Esc` с вопросом, безопасная запись, вопросы Far.
   - Строка статуса и строка клавиш Far, мышь (щелчок, колесо, двойной щелчок — слово), память позиции, история `Alt+F11`.
   - Слежение за файлом на диске.
2. **Агент, часть 1** — этап 1 раздела «Редактор и агент» (буфер, `afar_edit`, `afar_editor_state`, `afar_buffer_*`, хуки-ограждения, подсветка авторства, шаг отмены).
3. **Остальное из Far:** вертикальные блоки, постоянные блоки, `Alt+U/I`, `Ctrl+P/M`, поиск, замена, «найти всё», `Alt+F8`, закладки, `F8` / `Shift+F8`, ошибки кодировки, автоотступ, показ пробелов, полоса прокрутки, настройки редактора (`F9` в меню, `Alt+Shift+F9`), вставка путей (`Shift+Enter`, `Ctrl+[`…), диалог «уже открыт» целиком.
4. **Агент, части 2–4** — передача хода, маркеры, слой предложений (раздел «Редактор и агент»).
5. **Лучше, чем в Far:** подсветка синтаксиса (вместе с этапом 3 просмотрщика), перенос по словам и прочее.

## Редактор и агент

Редактор — место, где человек и агент работают **в одном тексте**: человек пишет, передаёт ход, агент читает написанное и дописывает следующими строками или правит текст; агент может открыть файл, прокрутить, выделить, подсветить, мигнуть фрагментом.

### Буфер — единственная правда

- Пока файл открыт в редакторе afar, агент **не пишет на диск**: все его изменения происходят в буфере редактора. Сохраняет человек — `F2`, как в Far.
- Текст изменений уходит агенту и обратно **по MCP**, а не через консоль агента.
- Агент не должен прочитать устаревший файл с диска или записать мимо буфера — это обеспечивают хуки ([«Ограждение»](#ограждение-хуки)).
- Если файл на диске изменился в обход буфера (например, Bash агента, внешняя программа), редактор спрашивает, как Far: перечитать или оставить своё.

### Три слоя

| Слой | Что это | Сохраняется в файл |
|---|---|---|
| **Текст** | Содержимое буфера. Ответ агента, дописанный в документ, становится текстом — документ сам становится диалогом (заметки, markdown, ТЗ) | да, по `F2` |
| **Предложения** | Правка агента, ещё не принятая человеком: удалённое зачёркнуто, добавленное подсвечено, как diff. Принять или отклонить — по куску или все сразу; отказ от правки агента стоит одну клавишу | только принятое |
| **Пометки** | Виртуальный текст и подсветка: заметка на полях у строки, подсветка диапазона, мигание, указатель агента — то же, что в просмотрщике ([«Агент открывает и показывает»](#агент-открывает-и-показывает)) | нет |

- **Авторство.** Текст агента подсвечен, пока человек его не принял (правкой, явным принятием или сохранением). Каждая порция агента — **один шаг отмены**: `Ctrl+Z` откатывает весь ответ агента целиком.
- **Сразу или предложением** — настройка `apply`: `direct` (правка сразу входит в текст, с подсветкой авторства), `propose` (всё — предложениями), `mixed` (по умолчанию: дописывание нового текста — сразу, изменение и удаление текста человека — предложением).

### Передача хода

Человек явно отдаёт ход агенту. Два способа, оба включены и настраиваются.

**Клавиша.**
- `Ctrl+Enter` — команда `editor.agent_turn` (в редакторе Far свободна; в просмотрщике та же клавиша — «спросить о выделенном»). Переназначается в раскладке клавиш.
- Без выделения — «твой ход»: агент получает изменения с прошлого раза, позицию курсора. С выделением — выделенное и есть предмет.
- Вариант с указанием: внизу редактора открывается однострочное поле, куда пишется короткий запрос агенту — не уходя из редактора. Клавиша — не `Ctrl+Shift+Enter` и не `Shift+Enter` (в Far они вставляют путь и имя файла); предварительно `Ctrl+Alt+Enter`, сверить при реализации.

**Маркер в тексте.**
- Строка, начинающаяся с маркера (`@agent …`), или маркер в комментарии кода (`// @agent исправь`).
- Варианты задают вид ответа (по мотивам `AI!`/`AI?` из aider): `@agent` — агент решает сам; `@agent?` — только ответ пометкой на полях, текст не трогать; `@agent!` — править текст.
- Срабатывает по `Enter` в конце строки с маркером (по настройке — ещё и по сохранению), а не в момент распознавания — иначе ход уйдёт посреди фразы.
- Срабатывают только маркеры, **набранные сейчас**; маркеры, бывшие в файле при открытии (например, документация про afar), игнорируются.
- Строка маркера — указание, а не содержимое: по умолчанию убирается, когда агент начал ответ.

**Автоматически по паузе** — выключено по умолчанию: тратит токены и дёргает агента посреди мысли.

**Что уходит агенту** при передаче хода — компактно, не весь файл:
```
[afar editor #3 notes.md v17 | user turn]
instruction: <текст маркера или поля указания, если есть>
changes since v12 (last seen by agent): <diff>
cursor 52:1, selection: none
```

**Настройки** (клавиши — в раскладке, остальное — `config.toml`):
```toml
[editor.agent]
markers = ["@agent"]          # several allowed: ["@agent", "@ai"]
marker_in_comments = true     # also match inside code comments
marker_trigger = "enter"      # enter | save | both
marker_remove = true          # remove the marker line once the agent replies
apply = "mixed"               # direct | propose | mixed
send = "diff"                 # diff since the agent's last view | full text
auto_turn_idle_s = 0          # 0 = off; otherwise pass the turn after a pause
```

### Во время хода агента

- В строке статуса редактора — индикатор «ход агента».
- Человек может продолжать печатать: правки агента задаются заменой по тексту (`old → new`), а не смещениями, и переживают правки человека выше по файлу.
- Отмена хода — клавишей в редакторе. Через MCP прервать агента нельзя: afar посылает `Esc` в PTY агента. Это сигнал управления, а не передача содержимого, — допустимое исключение из правила «не через консоль».

### Инструменты агента

| Инструмент | Что делает |
|---|---|
| `afar_edit` | открыть файл в редакторе на строке/по шаблону (новый экран, если пользователь занят другим — [«Этикет внимания»](#этикет-внимания)) |
| `afar_editor_state` | открытые редакторы: файл, версия буфера, изменён ли, курсор, видимые строки, выделение |
| `afar_buffer_read` | текст буфера (весь или диапазон) с номерами строк и версией; агент читает буфер, а не диск |
| `afar_buffer_edit` | замена `old` → `new` (как `Edit` Claude Code; `old` должен быть уникален, иначе ошибка); результат — по настройке `apply` |
| `afar_buffer_insert` | вставить текст после строки или после якорного фрагмента — «дописать ответ» |
| `afar_highlight` | пометки, мигание, заметки на полях — общий с просмотрщиком |

- У буфера — счётчик версий; afar помнит последнюю версию, которую видел агент, и отдаёт изменения от неё.
- Каждый вызов, меняющий буфер, — одна порция агента (один шаг отмены), запись в журнал с `actor = agent`.
- Права: правка буфера не меняет диск, поэтому подтверждения не требует; разрешения — через `permission(AgentAction)` ([02-architecture.md](02-architecture.md)) отдельным действием, чтобы её можно было запретить.

### Ограждение: хуки

Системный промпт подталкивает агента к инструментам буфера, а хук `PreToolUse` (matcher `Read|Edit|MultiEdit|Write|NotebookEdit`) гарантирует, что он их не обойдёт:
- **`Read`** файла, открытого в редакторе с несохранёнными изменениями, — отказ с причиной «файл открыт в редакторе afar с несохранёнными изменениями — используй `afar_buffer_read`». Если буфер не изменён, `Read` разрешён.
- **`Edit`/`Write`/`MultiEdit`** файла, открытого в редакторе, — отказ с причиной «файл открыт в редакторе afar; используй `afar_buffer_edit`». Вариант на проверку: вход хука содержит `old_string`/`new_string` — afar может сам положить правку в буфер предложением и ответить отказом с причиной «правка показана пользователю в редакторе как предложение». Как модель реагирует на такой отказ, проверить на живом агенте.
- Хук вызывается на каждый `Read`/`Edit`/`Write` агента, поэтому отвечает сразу: если в редакторе нет открытых файлов (или нет файла из запроса), afar разрешает без разбора входа. Пока редактора нет, этот хук не ставится.
- Bash агента (`sed -i` и т. п.) хуком надёжно не перехватить — остаётся вопрос редактора «файл изменён на диске».

### Этапы

0. **Эксперимент:** Channels и протокол IDE на живом `claude` ([«Связь с Claude Code»](#связь-с-claude-code)) — решающая проверка до начала работы над редактором.
1. Буфер, версии, `afar_edit`, `afar_editor_state`, `afar_buffer_read/edit/insert`, хуки-ограждения, подсветка авторства, шаг отмены на порцию агента. *Сделано 2026-10-07:* строки агента светло-зелёные до правки строки пользователем или сохранения; правки агента не двигают курсор и экран пользователя; разрешение `edit_buffer` (по умолчанию «можно»); журнал `edit` / `buffer`.
2. Передача хода клавишей (с полем указания), индикатор и отмена хода.
3. Маркеры в тексте с вариантами и настройками.
4. Слой предложений (принять/отклонить по кускам), режимы `apply`.

### Открытые вопросы

1. Если Channels недоступны (вход не через claude.ai/Console, Team/Enterprise без `channelsEnabled`) — запасной путь: клавиша хода вставляет в поле ввода агента ссылку (`at_mentioned`) и переводит фокус, человек нажимает `Enter`, а изменения буфера прикладывает хук `UserPromptSubmit`. Маркеры без Channels не работают.
2. `apply` по умолчанию: `mixed` или `direct`.
3. Маркеры в коде: какие синтаксисы комментариев распознавать (по расширению файла).

## Связь с Claude Code

Кроме MCP-сервера afar и хуков ([04-agent.md](04-agent.md)), просмотр и редактор используют ещё два канала. Оба — не стабильный публичный интерфейс; после обновления Claude Code их нужно перепроверять (дымовой тест при старте, см. риски в [06-roadmap.md](06-roadmap.md)).

### Channels: afar будит агента

Нужны для передачи хода из редактора: MCP-сервер сам присылает событие в работающую сессию, и агент начинает ход без ввода в консоли.

- Сервер объявляет возможность `experimental: {'claude/channel': {}}` и шлёт уведомление `notifications/claude/channel` с `content` (текст события) и `meta` (атрибуты).
- Агент простаивает — событие сразу начинает ход; агент занят — события копятся и приходят вместе на следующем ходу. Отвечает агент обычными MCP-инструментами.
- Транспорт — **stdio**, а MCP-сервер afar — HTTP. Мост — подкоманда `afar channel` (по образцу `afar hook`): `claude` запускает её как stdio-сервер, она подключается к afar по `AFAR_ENDPOINT`/`AFAR_TOKEN` и пересылает события.
- Research preview: свой (не из списка разрешённых) сервер подключается флагом `--dangerously-load-development-channels server:<имя>`; только интерактивный режим; нужен вход через claude.ai или ключ Console (не Bedrock/Vertex); в Team/Enterprise — включённый администратором `channelsEnabled`.
- Дополнительно: передача запросов разрешений (`experimental: {'claude/channel/permission': {}}`) — вопросы Claude Code «разрешить Bash/Edit?» можно показывать диалогами afar (например, когда фокус в редакторе); побеждает первый ответ — в терминале агента или в afar.
- **Настройка** `[agent] channels = true|false` в `config.toml` (по умолчанию — включено, если доступно). При старте afar проверяет, что канал поднялся (мост `afar channel` подключился); если нет — сообщение в строке статуса и запасной путь (открытый вопрос 1 в [«Редактор и агент»](#открытые-вопросы-1)).
- Документация: https://code.claude.com/docs/en/channels, https://code.claude.com/docs/en/channels-reference.

### Протокол IDE Claude Code

Тот же механизм, которым Claude Code связывается с VS Code и JetBrains: afar представляется ему как IDE. Протокол официально не описан (кроме раздела о встроенном MCP-сервере IDE в документации); разобран по claudecode.nvim (`PROTOCOL.md`, https://github.com/coder/claudecode.nvim) и проверен по коду Claude Code 2.1.291.

- **Подключение.** afar слушает WebSocket на `127.0.0.1:<порт>`, кладёт файл `<CLAUDE_CONFIG_DIR или ~/.claude>/ide/<порт>.lock` — JSON `{pid, workspaceFolders, ideName, transport: "ws", authToken}` (`pid` — живой процесс afar, иначе файл удаляется как устаревший) — и запускает агента с `CLAUDE_CODE_SSE_PORT=<порт>`: тогда `claude` подключается сам, без проверки каталогов. Токен — в заголовке `X-Claude-Code-Ide-Authorization`, подпротокол WebSocket `mcp`, обмен — MCP JSON-RPC. `NO_PROXY` должен включать `127.0.0.1`.
- **Что afar → агент:**
  - `selection_changed {text, filePath, selection}` — выделение; Claude Code прикрепляет его к следующему запросу пользователя;
  - `at_mentioned {filePath, lineStart, lineEnd}` — вставляет `@путь#L<a>-<b>` в поле ввода агента.
- **Что агент → afar:**
  - `openDiff` — правка на подтверждение (см. ниже); `close_tab`, `closeAllDiffTabs`;
  - `getDiagnostics` — модель видит его как `mcp__ide__getDiagnostics`; afar может отдавать пустой список (или позже — ошибки сборки);
  - `set_permission_mode` — служебный.
  Остальные инструменты из `PROTOCOL.md` (`openFile`, `getCurrentSelection`, `checkDocumentDirty`, `saveDocument`, …) текущая версия не вызывает.
- **`openDiff` и почему он не подходит редактору.** Вызывается только для `Edit`/`Write` и только когда Claude Code спрашивает разрешение; вопрос в терминале появляется одновременно. afar показывает diff и отвечает `FILE_SAVED` + итоговый текст или `DIFF_REJECTED`; **файл пишет сам `claude`** после принятия. Ответа «принято, но не сохраняй» нет, а отказ прерывает ход агента. Поэтому `openDiff` — только для проверки правок в файлах, *не* открытых в редакторе ([«Правки агента в открытом файле»](#правки-агента-в-открытом-файле)); правки в редакторе идут через инструменты буфера и хуки.
- **`workspaceFolders`** в lock-файле — отдельный каталог сессии afar, а не каталоги панелей: иначе другие сессии `claude`, запущенные в тех же каталогах, увидят afar в `/ide` и смогут к нему подключиться. Агент afar подключается по `CLAUDE_CODE_SSE_PORT` и каталоги не сверяет.
- **Lock-файл** — единственное, что afar кладёт в `~/.claude`: создаётся при старте, удаляется при выходе; после падения его убирает сам `claude` (`pid` не жив) или afar при следующем запуске (свои файлы с мёртвым `pid`); при перезапуске в режиме разработки переписывается с новым `pid`.
- MCP-сервер из `--mcp-config` не должен называться `ide` — это имя занято соединением с IDE.

### Эксперимент (2026-10-07, Claude Code 2.1.292)

Оба канала проверены на живом `claude` (`src/ide.rs`, `afar channel` в `src/mcp.rs`, `src/app/ide.rs`; включаются `[agent] ide` и `[agent] channels`). Обмен по протоколу IDE пишется в `<сессия>/ide.log`.

**Протокол IDE — работает.**
- `claude` с `CLAUDE_CODE_SSE_PORT` сам подключается через ~2 с после старта: `initialize` (протокол `2025-11-25`), `notifications/initialized`, `ide_connected {pid}`, `tools/list`. Подпротокол WebSocket `mcp` сервер должен вернуть в ответе (axum: `protocols(["mcp"])`).
- `selection_changed` без выделения (`isEmpty`) — в поле ввода агента появляется `[⧉ In CLAUDE.md]`; `at_mentioned {filePath, lineStart: 0, lineEnd: 11}` — вставляет `@CLAUDE.md#L1-12` (строки с нуля, `claude` прибавляет 1). Модель для этого не нужна.
- Пока `[⧉ In …]` горит, `claude` добавляет к каждому запросу «The user opened the file … in the IDE». Сообщение без `selection` он пропускает, а сообщение с `selection` заменяет всё его состояние. Поэтому, когда на экране не остаётся просмотрщика, afar один раз отправляет `selection_changed` с пустым `selection` и без `filePath`: индикатор и приписка исчезают.
- Каждый ход `claude` начинает с `closeAllDiffTabs`; после записи файла вызывает `getDiagnostics` для файла и для всех файлов — место, куда afar сможет отдавать ошибки сборки.
- `openDiff {old_file_path, new_file_path, new_file_contents, tab_name}` приходит **только когда Claude Code спрашивает разрешение**. В режиме по умолчанию у пользователя правки разрешаются без вопроса — `openDiff` не вызывается; с `--permission-mode default` вызывается. В терминале агента одновременно: «Opened changes in afar ⧉ … Do you want to create …». Ответ `FILE_SAVED` + текст — `claude` пишет файл и затем дважды вызывает `close_tab`.
- Lock-файл удаляется при выходе afar; если afar убит, файл остаётся (устаревший `claude` удаляет сам, когда ищет IDE по `pid`).

**Channels — работают.**
- Мост `afar channel` (stdio, `experimental: {'claude/channel': {}}`) забирает события у afar длинным опросом (`/hook/channel-wait`); событие `notifications/claude/channel {content, meta}` сразу начинает ход агента — проверено командой `afar:channel <текст>` в командной строке afar.
- **При каждом запуске** `claude` с `--dangerously-load-development-channels` спрашивает в своей панели подтверждение («I am using this for local development», Enter). В режиме разработки это значит — после каждой пересборки. Без флага запускаются только одобренные каналы (`--channels plugin:<имя>@<маркетплейс>`): из официального маркетплейса Anthropic или, в Team/Enterprise, из списка администратора `allowedChannelPlugins` в управляемых настройках; своего списка у пользователя нет, канал из своего маркетплейса всё равно требует флага; настройки, принимающей вопрос заранее, нет (документация Channels, проверено 2026-10-07).
- Поэтому — настройка `[agent] confirm_channels` (по умолчанию выключена, флажок под «Channels» в окне настроек агента): afar сам нажимает Enter, если в первую минуту после запуска на экране агента вопрос, в нём перечислен только его канал (`Channels: server:afar-channel`) и выбран пункт «I am using this for local development»; один раз за запуск, с сообщением в строке сообщений. Проверено на живом `claude`: вопрос пропускается, мост `afar channel` запускается. Надпись «server:afar-channel · no MCP server configured with that name» при старте — ложная тревога: Claude Code сверяет имя канала только с серверами из своих файлов настроек (enterprise, managed, user, project, local), серверы из `--mcp-config` в эту сверку не входят. Канал при этом регистрируется (проверено журналом `claude --debug`: «afar-channel: Channel notifications registered»).
