# 15. История и автозавершение в afar

Что хранят поля ввода и как помогают набирать: история полей диалогов, история команд, автозавершение в диалогах и командной строке. Сначала — **база как в Far** (справка: [14-far-history-autocomplete.md](14-far-history-autocomplete.md)), затем — **улучшения**, которые Far не умеет. Решено (2026-10-07): делать сейчас, до этапа 2 просмотрщика; все улучшения берём, но после базы.

## База: что берём из Far

- **История полей диалогов.** У поля есть имя списка (`Copy`, `NewFolder`, `Masks`, `SearchText`, `LineNumber`, …); поля с одним именем делят список. Запись — при закрытии диалога кнопкой (не по `Esc`). Повтор (без учёта регистра) поднимается наверх и сохраняет закрепление. У некоторых полей пустое поле сразу заполняется последней записью (F7, `Alt+F8`).
- **Список истории поля:** `Ctrl+Up` / `Ctrl+Down` или щелчок по стрелке `↓` справа от поля. Под полем (над ним, если внизу нет места), шириной с поле (не уже 21), до 8 строк; закреплённые первыми, дальше новые сверху. `Enter` / `Tab` — подставить, `Ins` — закрепить, `Shift+Del` — удалить запись, `Del` — очистить незакреплённые (с вопросом), `Ctrl+C` — копировать.
- **`Ctrl+End` в поле** — перебор по кругу записей, которые начинаются с набранного.
- **История команд** — та же модель (сейчас — `commands.txt` в `src/app/cmdline.rs`): `Ctrl+E` / `Ctrl+X`, `Ctrl+End`, позже `Alt+F8`.
- **Автозавершение** — один компонент для полей диалогов и командной строки. После каждого изменения текста (если нет ожидающего ввода) — немодальный список вариантов под полем (у командной строки — над ним), первый пункт пустой — это исходный ввод. Источники: история поля (по всей строке), файлы и папки (по последнему слову, с кавычками; у полей-путей), переменные `%VAR%`, программы из `PATH`/`PATHEXT` и `App Paths` (командная строка, если в слове нет `\` и `/`). `Up`/`Down` сразу подставляют вариант в поле, `Enter` закрывает список и действует дальше (выполняет команду, нажимает кнопку диалога), `Esc` только закрывает список, `Shift+Del` удаляет запись истории, `Ctrl+Space` вызывает список вручную.
- **Настройки автозавершения** (как окно Far «Настройка автозавершения»): показывать список, модальный режим, дописывать первый вариант; для каждого источника — всегда / только по `Ctrl+Space` / никогда.
- **Лимиты:** 1000 записей и 90 дней на список; сжатие при выходе удаляет незакреплённые записи, которые и старше 90 дней, и вне 1000 новых.

Отличия от Far, решённые сразу:
- **«Отмена» в историю не пишет** (в Far, судя по коду, пишет любая кнопка, кроме `Esc`, — не проверено на живом Far; запись по «Отмене» выглядит ошибкой).
- **Пути от папки панели:** относительный путь в поле дополняется от папки активной панели (как и выполняется), а не от текущего каталога процесса.
- **Перебор `PATH` кэшируется** (Far читает каталоги `PATH` на каждое нажатие клавиши); кэш сбрасывается раз в минуту и при смене `PATH`.

## Хранилище

**Одна база SQLite** `%LOCALAPPDATA%\afar\history.db` (крейт `rusqlite`, SQLite встроен в сборку) для всех историй: полей диалогов, команд, а позже — папок (`Alt+F12`), просмотра и правки (`Alt+F11`, туда же переедут позиции просмотрщика из `history\viewer.json`). Почему не JSON-файлы: улучшения требуют выборок (по папке, по частоте, по подстроке), несколько запущенных afar пишут в историю одновременно (WAL), а импорт из Far всё равно читает его SQLite-базу.

```sql
entry(id INTEGER PRIMARY KEY,
      kind TEXT,          -- 'dialog' | 'command' | 'folder' | 'view'
      list TEXT,          -- имя списка поля: 'Copy', 'Masks', … ('' у других видов)
      text TEXT,          -- сама строка
      folder TEXT,        -- папка, где запись сделана (активная панель)
      actor TEXT,         -- 'user' | 'agent'
      locked INTEGER,
      first_used INTEGER, last_used INTEGER, uses INTEGER,
      data TEXT)          -- JSON: у команд — код возврата и длительность; у просмотра — позиция и т. п.
use(entry_id, time, folder)  -- последние 20 использований записи: для частоты и «в этой папке»
```

- **Повтор** ищется в том же `kind` + `list` по `text` без учёта регистра (Windows): обновляются `last_used`, `uses`, регистр текста — новый, закрепление сохраняется; добавляется строка в `use`.
- **Сжатие** при выходе — правило Far (закреплённые не трогаются); `use` — не больше 20 строк на запись.
- **Переход:** при первом запуске `commands.txt` переносится в базу (`kind = 'command'`, папка неизвестна).

## История полей диалогов

Имена списков — из Far (тогда общие списки получаются сами):

| Поле afar | Список | Последняя запись в пустом поле |
|---|---|---|
| F5 / F6 — куда копировать / переносить | `Copy` | нет |
| F7 — имя папки | `NewFolder` | да |
| F7 — цель ссылки | `NewFolderLinkTarget` | нет |
| `Gray+` / `Gray-` — маска выделения | `Masks` | нет (своя маска `select_mask` — как в Far) |
| F7 в просмотрщике — что искать | `SearchText` | нет |
| `Alt+F8` в просмотрщике — перейти | `LineNumber` | да |
| Внешняя программа просмотра (настройки) | `ExternalViewer` | нет |
| Агент — команда, имя сессии, модель, указания `/compact` | `AgentCommand`, `AgentName`, `AgentModel`, `AgentCompact` | нет |

- В `dialog.rs` у поля вместо `history: bool` — `history: Option<&'static str>` и флаги `use_last`, `path` (поле с путями: автозавершение по файлам), `exec` (программы из `PATH`), `no_autocomplete`.
- Запись делает диалог при закрытии кнопкой, кроме «Отмены»: все поля с историей, включая пустые значения (как в Far).
- **Значения, подставленные агентом** (его `afar_copy` с подтверждением и т. п.), пишутся с `actor = 'agent'`: в списке они помечены, в «последнюю запись» и в верх порядка по умолчанию не попадают (улучшение 7).

## Улучшения (после базы)

### История

1. **Порядок по частоте и свежести, с учётом папки** («frecency», как zoxide). Вес записи: `Σ по использованиям 1 / (1 + дни_назад / 7)` × 2, если использование было в той же папке или её подпапке, что и сейчас. Закреплённые всё равно первые. Порядок «просто новые сверху» (как в Far) — настройкой.
2. **Фильтр набором в списке.** Печать в открытом списке сужает его: нечёткий поиск по подпоследовательности символов (`cpbk` находит `copy-backup`), найденные символы подсвечены, `Backspace` отменяет; лучшие совпадения — выше, при равенстве — по порядку из пункта 1.
3. **Подробности у записи** справа в списке (и полностью в строке под ним): когда, в какой папке; у команд — код возврата и длительность; у путей — существует ли путь: несуществующие серые (проверка в фоне, сетевые пути — с ограничением по времени).
4. **Больше источников для путей.** В списке поля «куда копировать» (и других полей с путями), после истории поля: путь пассивной панели, история папок (`Alt+F12`), закреплённые папки — каждая группа под своим заголовком-разделителем.
5. **Импорт истории Far.** При первом запуске (если найден профиль Far: `history.db` лежит в локальном профиле, `%LOCALAPPDATA%\Far Manager\Profile`) afar предлагает перенести истории команд, папок, просмотра и полей диалогов; повторно — пунктом меню. Таблица Far (`history(kind, key, name, time, lock, data)`, документ 14, §2) переводится в `entry` один к одному; время Far — в сотнях наносекунд от 1601 года.
6. **Приватность.** Команда, начатая с пробела, в историю не пишется (как `ignorespace` в bash). Явные секреты (`--password=…`, `token=…`, ключи вида `sk-…`, строки с `Authorization:`) заменяются на `***` при записи; правила — общие с маскировкой журнала (M3, `journal.redact`).
7. **Записи агента помечены** (`actor = 'agent'`, значок в списке). По умолчанию не поднимаются наверх и не подставляются как последняя запись; настройка — смешивать с записями пользователя.

### Автозавершение

8. **Подсказка-«призрак», как в fish.** Самое вероятное продолжение из истории (по порядку из пункта 1, в этой папке) показывается серым прямо в поле за курсором; `→` (в конце строки) или `End` принимают её целиком, `Ctrl+→` — по слову. Выпадающий список при этом не появляется сам — только по `Ctrl+Space` (настройкой — как в Far, на каждое изменение).
9. **Нечёткое совпадение** в списке автозавершения (как в пункте 2) с подсветкой найденных символов; совпадения с начала строки — выше.
10. **Порядок по контексту** — тот же расчёт, что в пункте 1.
11. **Пути от панелей.** Относительный путь — от папки активной панели; среди вариантов — имена из пассивной панели (для команд вида `copy x <имя на другой панели>`).
12. **Перебор в фоне.** Папки (особенно сетевые) читаются в фоновом потоке, список дополняется по мере чтения, ввод не ждёт; результаты перебора кэшируются на несколько секунд.
13. **Аргументы команд** (позже): подкоманды и ключи для частых программ (`git`, `cargo`, `npm`, `claude`), ветки и теги git; описания — небольшими файлами (по образцу описаний автодополнения fish), чтобы добавлять программы без перекомпиляции.
14. **С помощью агента** (позже, только явно): строка, начатая с `?` в командной строке (`?найди большие файлы за неделю`), уходит агенту с просьбой предложить команду; ответ подставляется в командную строку, пользователь проверяет и запускает сам. Тратит запросы — поэтому только по явному префиксу.

## Настройки

```toml
[history]
dialogs = true            # история полей диалогов
commands = true
skip_leading_space = true # команда с пробелом в начале не пишется
redact_secrets = true
order = "frecency"        # frecency | recent (как в Far)
agent_entries = "marked"  # marked (не наверх) | mixed
limit = 1000              # записей на список ...
lifetime_days = 90        # ... и дней (удаляются только вне обоих)

[autocomplete]
dialogs = true
command_line = true
suggest = "ghost"         # ghost (подсказка + список по Ctrl+Space) | list (как в Far) | off
modal = false
append_first = false      # Far: дописывать первый вариант с выделением
fuzzy = true
history = "always"        # always | ctrl_space | never — для каждого источника
files = "always"
variables = "always"
programs = "always"
```

Окна настроек: «Параметры → Настройки автозавершения» (как в Far, с пунктами afar) и флажки истории в «Параметры → Настройки диалогов» и «Системные параметры».

## Этапы

1. **База истории** (сделано 2026-10-07): хранилище SQLite, перенос `commands.txt`; имена списков у полей, запись при закрытии диалога; последняя запись в пустом поле (F7, `Alt+F8`); список по `Ctrl+Up`/`Ctrl+Down` и `↓` с закреплением и удалением; `Ctrl+End`.
2. **База автозавершения** (сделано 2026-10-07, кроме «подставлять первый вариант»; как в Far; ручного вызова в командной строке нет — `Ctrl+Space` переключает фокус на агента, а в Far ручной вызов при включённом автоматическом списке ничего не меняет): компонент для полей и командной строки, источники, немодальный список, окно настроек.
3. **Улучшения истории** (сделано 2026-10-07; закреплённых папок пока нет, подробности команд — в будущем меню `Alt+F8`): порядок по частоте и папке (1), фильтр набором (2), подробности (3), источники путей (4), приватность (6), пометка агента (7).
4. **Улучшения автозавершения** (сделано 2026-10-07): подсказка-«призрак» (8), нечёткое совпадение (9), порядок по контексту (10), пути от панелей (11), перебор в фоне (12). Отличия от замысла: призрак берёт продолжение из истории, а без него — из файлов и программ; имя с пробелом призрак предлагает только после открытой кавычки (вставить кавычку перед словом серым текстом нельзя); в командной строке списка по запросу нет (`Ctrl+Space` — фокус на агента), он есть в стиле `list`; медленная папка не дописывается в открытый список, а попадает в кэш и предлагается со следующей клавиши (ожидание чтения — 150 мс, кэш — 3 с).
5. **Импорт истории Far** (5; сделано 2026-10-07): `history.db` из локального профиля Far (`FARLOCALPROFILE`, иначе `%LOCALAPPDATA%\Far Manager\Profile`; запасные — `FARPROFILE` и `%APPDATA%`), открывается только для чтения (Far может работать). Каждая запись Far — использование в своё время: новая запись или ещё одно использование той же строки (закрепление сохраняется, если оно есть у любой); использование с тем же временем уже есть — запись пропускается, поэтому повторный импорт берёт только новое. Команды — с папкой запуска (поле `data` Far) и маскировкой секретов; папки и файлы плагинов (с `guid`) и пустые строки не берутся; история просмотра и правки — новый вид `view` (для будущего `Alt+F11`, тип Far — в `data`). Предлагается один раз при запуске (отметка в таблице `meta` базы), потом — «F9 → Команды → Импорт истории Far».
